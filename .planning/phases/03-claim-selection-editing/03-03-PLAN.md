<task type="auto">
  <name>Task 1: Implement modal claim editor with autosave</name>
  <files>frontend/claim_editor.py</files>
  <action>
Create a Streamlit dialog for editing a single claim candidate with autosave behavior.

- Define `open_claim_editor(claim_id, current_text, original_text)` using `@st.dialog`.
- Render a `st.text_area` bound to a stable key (e.g., `claim-edit-{claim_id}`) and use `on_change` to store edits in `st.session_state.claim_edits`.
- Add a "Reset to original" action that restores the original text in session state and updates the text area.
- Add a "Close" button that triggers `st.rerun()` to dismiss the dialog.
- Keep all keys ASCII and ensure dialog stays self-contained (no sidebar usage).
  </action>
  <verify>python -m py_compile frontend/claim_editor.py</verify>
  <done>Modal editor saves edits per claim in session state and can restore the original text.</done>
</task>

<task type="auto">
  <name>Task 2: Wire edit controls and hover originals in queue UI</name>
  <files>frontend/claim_queue.py</files>
  <action>
Integrate the modal editor into the queue rendering so each candidate claim can be edited.

- Import `open_claim_editor` and add an "Edit" button next to each candidate claim; clicking opens the dialog for that claim.
- Render edited claims in the queue (fallback to original when no edit exists).
- When a claim has been edited, render it with a hover tooltip showing the original text (use HTML `title` or a compact caption) and provide a reset control via the modal.
- Ensure edits persist across reruns and are keyed by queue item + claim index to avoid collisions.
  </action>
  <verify>python -m py_compile frontend/claim_queue.py</verify>
  <done>Queue items show edit controls and edited text with hover access to original wording.</done>
