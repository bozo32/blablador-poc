<task type="auto">
  <name>Task 1: Build TEI span index + excerpt/jump helpers</name>
  <files>
backend/attachment_spans.py
tests/test_attachment_spans.py
  </files>
  <action>
- Create `backend/attachment_spans.py` implementing a small, cache-friendly index over an attachment's TEI XML.
- Input source of truth: `backend/attachment_store.get_attachment(...).artifacts.tei_xml` and the TEI XML itself (do not rely on pre-enriched sentences).
- Parse TEI body into ordered paragraphs and sentences:
  - Paragraph boundaries: treat `tei:p`, `tei:item`, and `tei:cell` as paragraphs (bullets/tables count as paragraphs per phase context).
  - Sentence nodes: prefer `tei:s`; if no `tei:s` exists under a paragraph, fall back to a single sentence made from that paragraph's text.
  - Sentence ids: use `xml:id` when present; otherwise synthesize a stable id based on traversal index (e.g., `auto-sent-{i}`) so jump/excerpt still works.
  - Page label: derive from nearest `ancestor::tei:pb[1]/@n` when present; otherwise `"Unknown"`.
  - Section path: derive from ancestor `tei:div` headings.
    - Use the text content of `tei:head` nodes as labels.
    - Build a `section_path` like `"Introduction > Methods"` from outer-to-inner headings.
    - If no headings exist, return `"Body"` (do not synthesize headings).
- Provide public helpers used by the API:
  - `AttachmentSpanIndex.for_attachment(attachment_id, *, use_cache=True)`
  - `jump(span_id)` -> `{page, section_path, paragraph_id, sentence_id, sentence_index}`
  - `excerpt(span_id, before=2, after=1)` -> list of sentence payloads from the same paragraph only, marking which sentence(s) are highlighted.
- Add unit tests in `tests/test_attachment_spans.py`:
  - Excerpt does not cross paragraph boundaries.
  - Section path falls back to `Body` when no headings.
  - Jump returns page label when TEI contains `pb n=...`.
  </action>
  <verify>pytest -q</verify>
  <done>
- New module builds deterministic paragraph/sentence index from TEI.
- Excerpt API behavior is test-covered for paragraph boundary and section path rules.
  </done>
</task>

<task type="auto">
  <name>Task 2: Add attachment excerpt/jump + selection endpoints</name>
  <files>
backend/evidence_selection_store.py
backend/evidence_matching/serializers.py
backend/main.py
backend/schemas.py
tests/test_evidence_selection_store.py
  </files>
  <action>
- Create `backend/evidence_selection_store.py`:
  - Persist selection records on disk keyed by `claim_id` (claim_id is already claim-segment scoped in this app).
  - Storage location: a sibling directory to evidence runs (e.g., `data/evidence_selections/`). Use a `Path` constant or derive from settings; do not require any external service.
  - Selection schema to persist (JSON):
    - `claim_id`
    - `updated_at` (UTC ISO string)
    - `verdict`: `support|contradict|uncertain|none`
    - `primary`: `{candidate_id, attachment_id, span_id}` or `null` when verdict is `none`
    - `secondary`: list of `{candidate_id, attachment_id, span_id, rationale}` (optional)
    - `note`: optional string
  - Enforce phase rules:
    - `verdict=uncertain` requires non-empty `note`.
    - Each secondary entry requires non-empty `rationale`.
    - Allow `verdict=none` with no primary.

- Update `backend/evidence_matching/serializers.py` so every serialized candidate includes stable anchor metadata used by the UI:
  - Ensure `payload["metadata"]["attachment_id"]` is present (already set).
  - Add `payload["metadata"]["span_id"]` (or `anchor_id`) derived from the first span's `sentence_id` when spans exist.
  - Prefer not to mutate the candidate object; update only the serialized payload.

- Update `backend/schemas.py` with minimal pydantic models:
  - `AttachmentSpanJumpResponse`
  - `AttachmentSpanExcerptResponse` with a `sentences: list[{sentence_id, text, is_highlight, page, section_path, paragraph_id}]`
  - `EvidenceSelection*` request/response models.

- Wire endpoints in `backend/main.py`:
  - `GET /attachments/{attachment_id}/spans/{span_id}/jump` -> jump metadata via `AttachmentSpanIndex`.
  - `GET /attachments/{attachment_id}/spans/{span_id}/excerpt` -> excerpt payload (use defaults before=2, after=1; allow query overrides).
  - `GET /claims/{claim_id}/evidence/selection` -> current selection (404 -> return empty selection payload with `verdict` unset or `none`).
  - `PUT /claims/{claim_id}/evidence/selection` -> validate and persist selection.
- Return useful HTTP errors (404 for missing attachment/span; 422 for validation errors).

- Add tests in `tests/test_evidence_selection_store.py`:
  - uncertain requires note
  - secondary requires rationale
  - roundtrip write/read
  </action>
  <verify>pytest -q</verify>
  <done>
- New endpoints exist and return JSON payloads matching schemas.
- Evidence candidates include `metadata.span_id` so UI can request excerpt/jump.
- Selection persistence is validated and test-covered.
  </done>
