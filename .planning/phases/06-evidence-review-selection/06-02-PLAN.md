<task type="auto">
  <name>Task 2: Build evidence review UI (top hits + section groups + selection controls)</name>
  <files>
frontend/ui.py
frontend/assets/evidence_review.css
  </files>
  <action>
- Update `frontend/ui.py` evidence panel to align with Phase 06 context:
  - Add a main-pane mode toggle: `Citing` vs `Source`.
    - `Citing`: keep existing ranked card list as-is.
    - `Source`: render evidence review layout:
      - Show a “Top hits” section (choose a sensible default N like 5).
      - Then group remaining candidates by `section_path` (from candidate metadata or excerpt response). If missing, use `Body`.
      - Each candidate becomes an accordion row that, when expanded, fetches excerpt and renders:
        - two sentences before + highlighted sentence + one after (API default)
        - highlight styling for the sentence(s) marked `is_highlight`
        - metadata badges (label + score/confidence + page)
      - Collapsed preview: single-line preview + highlight badge (label + score).
  - Implement low-confidence de-emphasis:
    - Define a simple heuristic (e.g., combined score below threshold or label neutral) to apply a muted style class.
    - Still keep content accessible/clickable.
  - Fix label normalization so UI treats backend labels `entails/contradicts/neutral` correctly (current code uses `entail/contradict`).
  - Empty states:
    - If attachments not parsed (evidence API errors or attachment queue indicates not matched): show status message; disable selection controls.
    - If no candidates: show “None found” + clear existing next actions (rerun / check attachment status).

- Add `frontend/assets/evidence_review.css` for excerpt highlight + muted candidate styling (keep consistent with existing evidence.css tone; do not redesign the whole app).

- Selection controls (right rail):
  - Show current selection summary for the active claim.
  - Provide verdict buttons: `support`, `contradict`, `uncertain`, `none`.
  - Primary selection: allow selecting one candidate as primary (e.g., from Top hits list) and save via `put_evidence_selection`.
  - Secondary selections: allow adding 0+ candidates, each requiring a rationale input.
  - Enforce: verdict `uncertain` requires a note before save.
  - Persist `none` while keeping candidates visible and changeable.

  </action>
  <verify>pytest -q</verify>
  <done>
- Source view renders candidates grouped by section, with expandable excerpts and visible highlights.
- Reviewer can save verdict + selection per claim and see it restored on refresh.
- UI enforces uncertain note + secondary rationale constraints.
  </done>
