<task type="auto">
  <name>Update attachment persistence to support unassigned + archived + placement metadata</name>
  <files>backend/attachment_store.py</files>
  <action>
Modify `backend/attachment_store.py` to support attachments without a claim assignment.

Required changes:
- Allow `create_attachment(... claim_id=...)` to accept `claim_id: Optional[str]`.
- Add optional placement metadata to the stored record:
  - `citation_index: Optional[int]`
  - `target_id: Optional[str]`
- Add archive state:
  - `archived: bool` (default false)
  - `archived_at: Optional[str]`
- Add/update helpers:
  - `list_attachments(..., archived: Optional[bool] = False, public: bool = False)` (default: return only non-archived)
  - `set_archived(attachment_id, archived: bool)` that also logs a timeline event.
  - `set_placement(attachment_id, claim_id: Optional[str], doc_id: Optional[str], citation_index: Optional[int], target_id: Optional[str])` that logs a timeline event (for audit trail).

Backward compatibility:
- Existing claim-scoped list and status calls must still work.
- `public_view` must not expose backend file paths.
  </action>
  <verify>pytest -q</verify>
  <done>Attachment store can create/list unassigned records and archive/unarchive/placement updates persist on disk.</done>

- Add `PATCH /attachments/{attachment_id}` that applies archive and/or placement updates.

3) Add `tests/test_attachment_store_sources.py`:
- Cover creating an unassigned attachment, archiving it, and listing with default filters.
- Cover setting placement fields and verifying they persist.
