# Phase 09-07 Spec: Graph as Architecture (Cytoscape)

## Goal

Implement a demo-quality Cytoscape-based **Surfing** view in the workspace center pane that makes the graph's architectural role visible:

- Stable anchors are obvious and boring.
- Plurality begins at segmentation (user contributions diverge).
- Disagreement is visible as "heat" (attention routing, not truth adjudication).

This is deliberately small-scope and narrative-driven.

## Non-goals

- No scalable retrieval/indexing.
- No automatic truth adjudication.
- No automatic "resolution" of disagreement; disagreement remains inspectable.

## Integration with Current App

This spec introduces a **POC data mode** that ships a small dataset in-repo, plus a renderer upgrade that can later be pointed at live project data.

Workspace mapping (center pane):

- Reading: current Document view.
- Chasing: current Review view.
- Surfing: graph exploration view (this spec).

## Architectural Notes (important)

Anchoring must be robust to:

1) Reprocessing PDFs with updated parsing (GROBID versions, TEI changes).
2) Per-reviewer segmentation differences.

Therefore:

- Prefer **quote selectors** (`exact`, `prefix`, `suffix`) + **window fingerprints** over raw offsets/token indices.
- Treat offsets as best-effort UI hints, not invariants.

## Conceptual Model (must implement in POC mode)

### Canonical (stable) nodes

1) Work
- type: `Work`
- id: `work:<doi>`
- attrs: `doi`, `title`, `year`, `venue`, `languages[]`, `canonical_uri`
- invariant: 1 Work per DOI (language variants collapsed).

2) In-text citation anchor (trailing citing statement)
- type: `CiteAnchor`
- id: `citeanchor:<citing_work_doi>#<anchor_id>`
- attrs:
  - `citing_work_doi`
  - `anchor_text` (e.g. "(Smith 2020)")
  - `cited_work_dois[]`
  - `anchor_quote` (TextQuoteSelector-like: `exact/prefix/suffix`)
  - optional `window_fingerprint` (hash of normalized "preceding window")
- invariant: exists once identified; `<anchor_id>` should be deterministic from selectors/fingerprint.

### Non-canonical (plural) nodes

3) ClaimAtom (user-scoped segmentation)
- type: `ClaimAtom`
- id: `claimatom:<citing_work_doi>#<anchor_id>#<user_id>#<atom_id>`
- attrs:
  - `text`
  - optional `token_start/token_end` (UI hint only)
  - `created_by`, `created_at`, `language`, `segmentation_notes`
  - `quote_selector` (anchor within the CiteAnchor preceding window)
- invariant: multiple atoms may coexist for the same citing span.

4) ClaimAnchor (coordination object, not truth)
- type: `ClaimAnchor`
- id: `claimanchor:<citing_work_doi>#<anchor_id>#<cluster_id>`
- attrs: `canonical_label` (editable), `created_by`, `created_at`, `status`, `member_count`

/**
 * ARCHITECTURE NOTE:
 * ClaimAnchor nodes are not truth claims. They are coordination anchors that
 * allow plural user segmentations (ClaimAtoms) to align without canonicalizing
 * interpretation. The system preserves disagreement; it does not resolve it.
 */

5) EvidenceSpan (first-class evidence object)
- type: `EvidenceSpan`
- id: `evidence:<cited_work_doi>#<span_id>`
- attrs:
  - `cited_work_doi`
  - `quote_or_snippet`
  - `quote_selector` (exact/prefix/suffix)
  - optional `locator` (page/section)
  - `created_by`

### Reified edges via Assertion nodes (preferred)

6) Assertion (attributable record)
- type: `Assertion`
- id: `assertion:<user_id>:<claimanchor_id>:<evidence_id>:<timestamp>`
- attrs: `relation_type` (supports/contradicts/unclear/partial), `rationale`, `created_by`, `created_at`, optional `confidence`

/**
 * GOVERNANCE NOTE:
 * Assertions are attributable records of who linked what evidence to what claim
 * with what relation type. Sanctions/rewards are out-of-band (institutional),
 * not automated by this system.
 */

## Edges (typed)

Canonical:
- `CITES`: `CiteAnchor -> Work` (cited)
- `IN_WORK`: `CiteAnchor -> Work` (citing) (direction can be reversed; must be consistent)

Plurality:
- `PROPOSES_ATOM`: `User -> ClaimAtom`
- `DERIVED_FROM`: `ClaimAtom -> CiteAnchor`
- `MAPS_TO`: `ClaimAtom -> ClaimAnchor`
- `ABOUT`: `Assertion -> ClaimAnchor`
- `CITES_EVIDENCE`: `Assertion -> EvidenceSpan`

## Heat

Compute heat per `ClaimAnchor` in the focused subgraph:

- Collect linked Assertions.
- heat = (#Assertions) * entropy(relation_type distribution)

/**
 * HEAT NOTE:
 * Heat is computed from disagreement density and diversity of judgments.
 * Heat is an attention-routing signal, not a correctness score.
 */

UI must explain: "Heat is disagreement density, not correctness."

## POC Dataset (must ship)

Create `data/poc_graph.json`:

- 3 Works (one citing, two cited)
- 1 CiteAnchor that cites both cited works
- 2 Users
- Divergent segmentation:
  - u1 splits into 2 atoms
  - u2 splits into 3 atoms
- 2+ ClaimAnchors showing partial convergence
- 3-5 EvidenceSpans
- 3+ Assertions with mixed relation types (to produce at least one high-heat ClaimAnchor)

## UI Requirements (Surfing / Cytoscape)

Layout:

- Left: select a citing Work, then list its CiteAnchors.
- Center: Cytoscape graph.
- Right: Architecture Inspector (selection-driven).

Required toggles:

- Show/Hide ClaimAtoms
- Show/Hide EvidenceSpans
- Show/Hide Assertions
- Canonical-only view

Noise rule (important):

- Default graph view should **not** render long node/edge labels directly on the canvas.
- Use hover tooltips and the right-side inspector for text.
- Optional: a "Show labels" debug toggle is allowed, but must default off.

Inspector must clearly state:

- Anchors are stable.
- Atoms are user contributions.
- ClaimAnchors coordinate; they are not truth.
- Assertions are attributable; the system does not decide.

## Acceptance Criteria

1) Selecting a CiteAnchor shows stable anchors + plural contributions + mapped ClaimAnchors + evidence/assertions.
2) At least one ClaimAnchor shows high heat due to mixed relation types.
3) Inspector distinguishes canonical vs plural, and coordination vs adjudication.
4) Canonical-only view is clean but uninformative ("the fun begins with segmentation").
