<task type="auto">
  <name>Task 1: Add pinned Python requirements for containers</name>
  <files>requirements/app.in, requirements/app.lock.txt</files>
  <action>
Create `requirements/app.in` containing the minimal set of runtime deps needed for `backend/` + `frontend/` to start.

Constraints:
- Pin `numpy<2` (known ABI breakage risk).
- Use a lockfile approach that works in Docker builds; generate a fully pinned `requirements/app.lock.txt`.
- Do not remove or modify `environment.yml` or the host-run workflow (`application.py`).

Implementation notes:
- Use `pip-tools` (`pip-compile`) to generate the lockfile.
- Keep the lockfile deterministic (sorted, pinned versions).
  </action>
  <verify>
  python -m pip install -q pip-tools && pip-compile --quiet --generate-hashes -o requirements/app.lock.txt requirements/app.in
  </verify>
  <done>
  `requirements/app.lock.txt` exists, pins versions (including `numpy<2`), and can be installed via `pip install -r requirements/app.lock.txt`.
  </done>
</task>

<task type="auto">
  <name>Task 2: Add Dockerfiles for API and UI (shared deps)</name>
  <files>docker/app-api/Dockerfile, docker/app-ui/Dockerfile, .dockerignore</files>
  <action>
Create two images:
- `docker/app-api/Dockerfile`: runs `uvicorn backend.main:app --host 0.0.0.0 --port 8000`.
- `docker/app-ui/Dockerfile`: runs `streamlit run frontend/ui.py --server.port 8501 --server.address 0.0.0.0`.

Constraints:
- Use Python 3.10 base image.
- Install deps from `requirements/app.lock.txt`.
- Set working directory to `/app`, copy repo code into the image.
- Add `.dockerignore` to exclude `data/`, `__pycache__/`, `.git/`, and large local artifacts.
  </action>
  <verify>docker build -f docker/app-api/Dockerfile .</verify>
  <done>Both Dockerfiles build successfully on the host.</done>
</task>
