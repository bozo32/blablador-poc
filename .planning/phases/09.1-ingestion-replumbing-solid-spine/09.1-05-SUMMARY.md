# Phase 9.1 Plan 05: Primary Extraction Attempts/Jobs + S3 Artifacts Summary

**Primary extraction now records durable attempts/jobs in Postgres, writes TEI + extraction JSON artifacts to MinIO/S3, and registers those artifacts in Postgres while keeping the existing ingestion metadata + filesystem outputs working.**

## Accomplishments

- Added minimal Postgres-backed spine helpers for attempts/jobs/artifacts with stable `settings_hash` idempotency
- Wired both the background ingest pipeline and the `/ingest/{doc_id}/extract` endpoint to:
  - create/reuse a primary attempt
  - create a worker job record
  - persist `tei.xml` + `extraction.json` to S3 under `extract/{work_id}/attempts/{attempt_id}/primary/*`
  - register artifact rows in Postgres
  - transition attempt state to `succeeded|partial|failed`
- Persisted `spine.active_attempt_id` into legacy `data/ingestion/.../metadata.json` for compatibility

## Task Commits

1. **Task 1: Implement attempts/jobs/artifacts spine helpers** - `bb7393f` (feat)
2. **Task 2: Wire extraction to spine + S3 artifacts** - `1fae25b` (feat)

## Deviations / Fixes

- Fixed attempt state transitions to avoid Postgres parameter-type ambiguity (casts via `COALESCE(%s::text, ...)`).
- Added a per-attempt advisory transaction lock keyed by `settings_hash` to prevent concurrent duplicate attempt inserts (background `auto_process` + explicit extract calls can race).
- Made artifact creation idempotent by returning an existing row for `(attempt_id, artifact_type, object_key)`.

## Verification Notes

- `POST /ingest` then `POST /ingest/{doc_id}/extract` produces:
  - one logical attempt for `(work_id, kind=primary, settings_hash)`
  - at least one job row
  - two artifact rows (TEI + extraction JSON) with matching S3 object keys
