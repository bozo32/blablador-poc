# Phase 9.1 Plan 08: Identity Split Scaffolding Summary

**Added the core identity tables needed to stop treating sha256 as a bibliographic Work identity: global `documents`, per-bytes `document_versions`, and project membership via `project_documents`. Ingest now dual-writes these records without breaking existing flows.**

## Accomplishments

- Added Postgres tables + indexes:
  - `documents(document_id, created_by_user_id, biblio_work_id, ...)`
  - `document_versions(document_version_id, document_id, sha256 UNIQUE, pdf_object_key, ...)`
  - `project_documents(project_id, document_id, ...)`
- Added helpers in `backend/spine/documents.py`
- Updated `POST /ingest` to create:
  - `documents` row
  - `document_versions` row using the upload sha256 + S3 object key
  - `project_documents` membership row

## Transitional Contract

- Until reconciliation/merge UI exists, `document_id` and `document_version_id` are set to the legacy `doc_id`.
- Existing `works`/`attempts` flow remains unchanged; this plan only adds identity scaffolding.

## Verification

- New ingest creates rows in `documents`, `document_versions`, and `project_documents` for the returned `doc_id`.
