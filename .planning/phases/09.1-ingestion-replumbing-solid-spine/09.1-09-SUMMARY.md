# Phase 9.1 Plan 09: Spine Read Default + Legacy Fallback Summary

**Flipped ingestion reads to prefer the Postgres+S3 spine while keeping the legacy filesystem ingestion store as a fallback.**

## What Changed

- Added `backend/spine/ingest_view.py` to build legacy-compatible ingest payloads from:
  - `works` (upload metadata)
  - latest `attempts` (extraction state)
  - `artifacts` + S3 (extraction.json + tei.xml)
- Updated API endpoints in `backend/main.py`:
  - `GET /ingest` and `GET /ingest/{doc_id}` prefer spine reads (merge with legacy when present)
  - `GET /ingest/{doc_id}/extraction` prefers spine-backed extraction.json
  - `GET /ingest/{doc_id}/body` prefers TEI from S3 artifacts
- Added rollback switch: `SPINE_READS=0` forces legacy reads

## Verification

- Ingest + extract a fresh PDF
- Confirm:
  - `GET /ingest/{doc_id}` returns a complete extraction stage without relying on local files
  - `GET /ingest/{doc_id}/body` returns paragraphs
  - `SPINE_READS=0` returns legacy ingestion list/get
