# Phase 9.1 Plan 12: Spine PDF Source for Extraction Summary

**Extraction no longer depends on `data/ingestion/**/source.pdf` at runtime; it downloads the PDF from S3 (MinIO) using spine metadata and feeds a temp file path to GROBID.**

## What Changed

- Added `backend/spine/pdf_source.py`:
  - `resolve_pdf_object_key(...)` resolves `pdf_object_key` from (a) ingest metadata `spine.pdf_object_key` or (b) Postgres `works.pdf_object_key`.
  - `get_pdf_temp_path(...)` downloads the PDF from S3 to a local temp file and returns the path.
  - `cleanup_temp_path(...)` removes the temp file best-effort.
- Added streaming download helper `download_to_path(...)` in `backend/object_store/s3.py`.
- Updated extraction callers to use spine PDF source by default:
  - `backend/main.py` `/ingest/{doc_id}/extract`
  - `backend/ingest_pipeline.py` background ingest worker

## Flags / Rollback

- `SPINE_PDF_SOURCE=legacy` forces extraction to read legacy local `source.pdf` via `get_document_source_path(...)`.

## Verification

- Brought up dev stack (`bash scripts/dev/up.sh`).
- Ingested `fixtures/sample.pdf` with `auto_process=false`, deleted `data/ingestion/<doc_id>/source.pdf`, and confirmed `POST /ingest/<doc_id>/extract` succeeds.
