# Phase 9.1 Plan 13: Spine-Backed Resolution Artifacts Summary

**Reference resolution results are now persisted in the ingestion spine (S3 + Postgres artifacts) and can be read back even if the legacy filesystem `metadata.json` is missing.**

## What Changed

- On `POST /ingest/{doc_id}/resolve` (`backend/main.py`):
  - Resolution output is written to S3:
    - `resolve/{work_id}/attempts/{attempt_id}/primary/resolution.json`
  - A Postgres artifacts row is created:
    - `artifact_type=resolution.json`
  - Resolution now treats missing `references` as `[]` (so the endpoint can still complete and persist an artifact).
- On `GET /ingest/{doc_id}/resolution` (`backend/main.py`):
  - Prefer spine reads when `SPINE_READS=1` (default) using resolution artifacts; fallback to legacy ingestion store.
- Spine view now surfaces resolution status/data when available (`backend/spine/ingest_view.py`).
- Background ingest pipeline also persists `resolution.json` artifacts when it performs resolution (`backend/ingest_pipeline.py`).

## Flags / Rollback

- `SPINE_READS=0` forces legacy reads.

## Verification

- Ingested `fixtures/sample.pdf`, ran extract + resolve, and confirmed `GET /ingest/{doc_id}/resolution` returns JSON.
- Temporarily removed `data/ingestion/{doc_id}/metadata.json` and confirmed `GET /ingest/{doc_id}/resolution` still succeeds via spine artifacts.
