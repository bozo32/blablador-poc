# Phase 9.1 Plan 14: Project Membership-Based Ingest Listing Summary

**`GET /ingest` now prefers a spine-backed list driven by project membership (`project_documents`) and PDF identity (`document_versions`), instead of relying on filesystem directory scans.**

## What Changed

- Added spine list primitives in `backend/spine/documents.py`:
  - `list_project_documents(project_id, limit)`
  - `get_latest_document_version(document_id)`
  - `is_document_in_project(project_id, document_id)`
- Added spine list view in `backend/spine/ingest_view.py`:
  - `list_ingests_from_spine(project_id, limit)` builds the same shape as `GET /ingest` documents using:
    - membership (`project_documents`)
    - latest `document_versions` (sha256, size, filename, pdf_object_key)
    - latest attempts + artifacts for stage state
  - `build_ingested_document_from_spine(...)` now enforces project membership
- Switched `GET /ingest` spine path in `backend/main.py` to use `list_ingests_from_spine(...)` (legacy merge fallback preserved).
- Added `document_versions.filename` to schema in `backend/db/migrate.py` and write it during ingest upload.

## Rollback

- `SPINE_READS=0` forces legacy filesystem listing/reads.

## Verification

- Confirmed import: `python -c "from backend.spine.ingest_view import list_ingests_from_spine; print('ok')"`.
- Confirmed `GET /ingest` returns successfully even with `data/ingestion/` temporarily removed (spine list only).
