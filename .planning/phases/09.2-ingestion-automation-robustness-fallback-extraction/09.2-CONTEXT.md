# Phase 9.2: Ingestion Automation Robustness + Fallback Extraction (INSERTED)

## Why This Phase Exists

We are increasing ingestion automation and using the live graph as a navigation surface.
In practice, ingestion fails in novel ways when PDFs are messy or external services (GROBID) choke.
We need a robust fallback that preserves progress and keeps users unblocked.

## Primary Goal

When structured TEI extraction fails, the system automatically runs a deterministic fallback to extract usable body text and a bibliography, with provenance and uncertainty labels. The UI also supports manual "force fallback" for low-quality TEI cases.

Persistence contract: fallback outputs are stored as versioned attempts/stages on the Work (job/attempt spine from Phase 9.1), with artifacts in the object store and metadata/quality flags in Postgres.

## Constraints

- Prefer incremental changes with clear rollback (small commits, tests).
- Never silently replace high-fidelity TEI with fallback output.
- Persist quality flags so downstream features can make conservative choices.

## Current Observations

- GROBID can 500 in `processHeaderDocument` due to `HeaderParser` NPE (`persons` null).
- Connection refused errors occur during startup; we should treat them as transient.

## Policy Decisions (Locked)

- If `processHeaderDocument` fails, still attempt `processReferences` (refs-only is acceptable; record header failure as quality flag).
- Fallback runs asynchronously as a background job; UI polls and shows progress.
- OCR is included as part of fallback via hybrid per-page policy (text layer first; OCR only low-coverage pages) with adaptive DPI (150 -> 200 -> 300).
- When fallback is `partial` or OCR-derived, index/search can proceed immediately with warnings; reference resolution is gated and prompts at resolution time when refs quality is low.

## Entry Criteria

- Baseline ingestion pipeline remains working for normal PDFs.
- A representative "GROBID choker" PDF exists for regression.

## Exit Criteria

- Users can recover from extraction failure via fallback.
- Ingest document metadata persists fallback results + quality flags.
- Tests cover the header-500 edge case and fallback path.
