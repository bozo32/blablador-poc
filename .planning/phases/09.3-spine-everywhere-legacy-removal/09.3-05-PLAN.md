# 09.3-05: Graph Stores Strategy

## Decision

The product expectation is that the graph becomes a durable workboard for navigation
("what is left to do"), not only a derived visualization.

Therefore:

- Persist all user-authored graph/workboard state in Postgres.
- Treat any remaining local graph DBs as disposable caches only.

Reference: `.planning/architecture/GRAPH_WORKBOARD_CORE.md`.

## Scope

Minimum for Phase 09.3:

- No durable local `data/graph.db` / `data/claims.db` files are required for core workflows.
- Reviewer progress state (checked/roles/assertions/votes/manual edges) survives restarts.

It is acceptable to keep derived indexing rebuildable and/or cached.

## Verification

- Start from empty `./data`.
- Ingest 1-2 PDFs, run extraction/resolution.
- Confirm graph-dependent UI features work (citation context / claim navigation) without requiring local `.db` files.

- Confirm that "work left" state survives restart (at minimum: checked marks + current selection assertion).
