Make pipeline stage boundaries explicit by defining a minimal, versioned contract envelope for each stage and a spine-backed persistence layer for those artifacts.

Purpose: Enable swapping implementations (e.g. rerankers) without rewriting callers by standardizing what each stage produces and how it is stored/fetched.
Output: Contract models + upgrade shims + Postgres tables + S3 persistence helpers + minimal API to store/fetch per-run stage artifacts.
</objective>

  <name>Task 1: Add v1 pipeline contract models + upgrade shim</name>
  <files>backend/contracts/__init__.py, backend/contracts/pipeline_v1.py, backend/contracts/upgrade.py</files>
  <action>
Create contract models for the Phase 10 stage arc.

Implement `backend/contracts/pipeline_v1.py` using Pydantic v2 with:
- A single common envelope used by every stage: `schema_version` (int), `artifact_type` (str; `contracts/{stage}@v{schema_version}`), `run_id` (uuid string), `stage` (one of `extract|citespans|retrieval|filter|rerank|nli`), `work_id` (canonical) and `doc_id` as an accepted alias, `created_at` (Z timestamp), `status` (`complete|partial|error`), `warnings` (list[str]), optional `error` object `{code,message,detail,retryable}`, `caps` with defaults candidates=200/rerank=50/nli=12, optional `component` metadata (implementation id/version/config_hash), and `input_fingerprint` (sha256-like string).

- Stage-specific `data` blocks with minimal, explicit shapes (keep types permissive where needed):
  - `extract`: `structured_doc` (the existing extraction.json payload) + `citation_anchors[]` (citation_index + reference_id + target_id + callout + window_text + sentence_id).
  - `citespans`: `by_target` mapping where each target has anchors containing `citation_index`, `span_id`, `selectors.quote {exact,prefix,suffix}`, and `window_fingerprint`.
- `retrieval|filter|rerank|nli`: candidate lists grouped by `target_id` with a stable `candidate_id` rule (deterministic per run), plus required text fields (full paragraph text) and normalized score slots.

- Deterministic helpers (used by service/persistence):
  - `artifact_type_for(stage, schema_version)`
  - `stage_object_key(run_id, stage)` -> `pipeline/{run_id}/{stage}.json`
  - `deterministic_json_bytes(obj)` using `json.dumps(... ensure_ascii=True, sort_keys=True, separators=(",", ":"))`.
  - `span_id_for(...)` (single canonical spec; stable across re-extraction):
    - Signature (suggested): `span_id_for(*, work_id: str, kind: str, quote: dict, window_fingerprint: str | None = None) -> str`.
    - Canonical inputs:
      - `work_id`
      - `kind` (e.g. `citation_window`)
      - `quote` selector dict with exactly `{exact,prefix,suffix}` (strings; empty allowed)
      - optional `window_fingerprint` if available
    - Algorithm: build canonical dict with exactly those keys, compute `sha256(deterministic_json_bytes(dict))`, return `span:{hex}`.
    - Compatibility rule: must match the repo's existing deterministic span id generation in `backend/span_graph_store.py` (use that implementation as the source of truth if needed).
  - `candidate_id_for(...)` (single canonical spec used everywhere):
    - Signature (suggested): `candidate_id_for(*, run_id: str, stage: str, target_id: str, source_doc_id: str, selector: dict, window_fingerprint: str | None = None) -> str`.
    - Canonical inputs:
      - `run_id` (uuid string)
      - `stage` (one of `retrieval|filter|rerank|nli`)
      - `target_id`
      - `source_doc_id` (the doc the paragraph came from; do not use `work_id`)
      - `selector` (the candidate paragraph selector; use the same selector shape you include in the candidate payload, not free-form text)
      - optional `window_fingerprint` if already computed upstream (include only if present)
    - Algorithm: build a canonical dict with exactly those keys, compute `sha256(deterministic_json_bytes(dict))`, return hex digest (optionally prefixed with `cand_`).
    - Rule: identical logical candidates MUST produce identical `candidate_id` across components; changing non-identity fields (scores, reasoning) MUST NOT change `candidate_id`.

Implement `backend/contracts/upgrade.py`:
- `upgrade_contract_payload(payload: dict) -> dict` that upgrades older schema versions to the latest supported version (v1 initially; keep structure ready for v2).
- `validate_contract_payload(payload: dict) -> dict` that upgrades then validates against the correct stage model, raising a helpful error on mismatch.

Constraints:
- Additive-only evolution (no renames/removals in-place).
- Keep the envelope consistent across all stages; avoid stage-specific top-level fields.

  <files>backend/spine/pipeline_runs.py, backend/spine/pipeline_artifacts.py, backend/db/migrate.py, tests/conftest.py, tests/test_pipeline_contract_store.py</files>
  <action>
Implement the spine-backed persistence layer for pipeline contract artifacts.

1) Schema (idempotent DDL) in `backend/db/migrate.py`:
- Add a new Phase 10 section creating:
  - `pipeline_runs` (run_id text PK, project_id, created_by_user_id, work_id text, created_at, input_fingerprint text, caps_json jsonb, settings_json jsonb default '{}', note text null)
  - `pipeline_stage_artifacts` (artifact_id text PK, run_id text REFERENCES pipeline_runs(run_id) ON DELETE CASCADE, project_id, created_by_user_id, stage text, schema_version int, artifact_type text, object_key text, bytes bigint null, content_type text null, created_at)
  - Unique index: `(run_id, stage)` to enforce “one artifact per stage per run”.
  - Helpful indexes: `pipeline_runs(work_id, created_at desc)` and `pipeline_stage_artifacts(run_id)`.

2) Run helpers (`backend/spine/pipeline_runs.py`):
- `create_run(work_id, *, caps, settings_json, input_fingerprint, note=None) -> dict` (generates UUID run_id).
- `get_run(run_id) -> dict|None`.

3) Artifact helpers (`backend/spine/pipeline_artifacts.py`):
- `put_stage_payload(*, payload_dict: dict) -> dict`:
  - Validate/upgrade payload via `backend/contracts/upgrade.py`.
  - Enforce write-once immutability per `(run_id, stage)` in a race-safe way:
    - Compute `object_key = pipeline/{run_id}/{stage}.json`.
    - Reserve the pointer row FIRST using a single atomic insert:
      - `INSERT INTO pipeline_stage_artifacts (...) VALUES (...) ON CONFLICT (run_id, stage) DO NOTHING RETURNING artifact_id`
      - If no row returned: raise a specific conflict error (e.g. `StageArtifactAlreadyExists`) and DO NOT write to S3.
    - Then serialize deterministically (see Task 1) and write bytes to S3 via `backend/object_store/s3.put_bytes(... content_type='application/json')`.
    - If S3 put fails: delete the reserved pointer row (by `artifact_id`) so a later retry can succeed.
    - If S3 put succeeds: update the pointer row with `bytes` (and any other final fields).
- `get_stage_payload(run_id, stage) -> dict|None`:
  - Look up pointer row, fetch bytes from S3, parse JSON, upgrade+validate, return dict.

4) Test isolation:
- Update `tests/conftest.py` truncation list to include `pipeline_stage_artifacts` and `pipeline_runs` (keep it consistent with `/dev/wipe`).

5) Add `tests/test_pipeline_contract_store.py` covering:
- Persisting a minimal `extract@v1` payload writes S3 object `pipeline/{run_id}/extract.json` and creates the Postgres pointer row.
- Round-trip `get_stage_payload()` returns a dict with required envelope fields.
 - Second call to `put_stage_payload()` for the same `(run_id, stage)` fails with a conflict error and does not overwrite the existing S3 object (GET returns the first payload).

Constraints:
- Immutability rule: stable per-run per-stage S3 key is write-once; reject second writes with a conflict error.
- Do not introduce new buckets; use the existing works bucket and existing S3 wrapper.
