<objective>
Ship a single predictable happy-path workflow: claimspan finalization mints a new run and drives background processing (through NLI) while the reviewer sees a citation-ordered requested-works queue and per-target run status.

Purpose: Make the core reviewer workflow simple and observable by introducing a thin orchestrator/state machine over immutable Phase 10-01 stage artifacts, backed by mutable Postgres run status and Streamlit polling UX.
Output: New run-status tables + /workflow API surface + happy-path orchestrator + Streamlit queue/status UX + tests + compose-backed verifier script.
</objective>

3) Orchestrator stage machine (happy path):
- For each run:
  - Mark run `running`, append `run_started` event.
  - Ensure `extract` and `citespans` stage artifacts exist (write once via `pipeline_contracts_service.store_stage`). If already exist (409), treat as OK and continue.
  - For each target in citation order:
    - If cancelled: skip and keep state `cancelled`.
    - If no attachment available: set `blocked` and continue; run remains resumable.
    - If attachment available: set target state `processing`, append stage-start events.
  - Produce and store terminal stage artifacts (write once):
    - MVP minimum: write `retrieval`, `filter`, `rerank`, `nli` artifacts with `data.by_target` for all targets that reached runnable state.

      - If all runnable targets succeeded => stage status `complete`.
      - If some targets errored/timed out/cancelled/blocked => stage status `partial` and write warnings/error summaries at envelope level.
    - IMPORTANT: do not write stage artifacts until you have a terminal outcome snapshot for that stage across targets (because artifacts are immutable).
  - Update per-target `stage_state_json` and `attempts_json` while work proceeds (mutable tables).
  - Retries/timeouts:
    - Track retry counts per target per stage in `attempts_json`.

  - Terminal run state:
    - If all targets done (including cancelled) => `complete`.
    - Mixed done + errors/blocked => `partial`.
    - Only error and no progress => `error`.
    - If all targets cancelled => `cancelled`.
