  <name>Task 1: Unified dropzone + Intake Inbox (classify, hold unknown, route citing)</name>
  <files>frontend/ui.py, frontend/ingestion_api.py</files>
  <action>
Implement unified Intake at the top of the left pane:

- Add a top-of-left-pane “Drop PDFs” control accepting multiple PDFs.
- On drop: create an Intake Inbox row per file with intent `citing | source | unknown`.
- Best-effort auto-classify ("auto-classify then ask") using lightweight signals:
  - If a citing doc is selected and user is in Review/Chase, default to `source`.
  - If the PDF appears to contain bibliography/citation callouts (best-effort), default to `citing`.
  - Otherwise `unknown`.
- Unknown rows show a clickable `?` menu to choose Citing vs Source (with optional “attach now” when context exists).
- Only submit when intent != `unknown`.
- Routing:
  - `citing`: call existing ingest upload helper and auto trigger extract+resolve.
  - `source`: enqueue the file into the Source upload queue via `attachment_queue` (upload mechanics handled in 10-04.5-01-05).

Project scoping (do not skip):
- Ensure every `/ingest*` request includes `X-Project-Id` so citing intake continues to work after backend enforcement in `10-04.5-01-04`.
- Implement this by updating `frontend/ingestion_api.py` to accept a `project_id` (or read the UI-selected project id) and set `headers={"X-Project-Id": project_id}` on upload + list/read calls.
- Update `frontend/ui.py` to pass the selected project id into the ingestion helper.

Duplicate + near-duplicate behavior (UI):
- Exact duplicate `citing` should create a new DocumentVersion under the same Work and show a small note.
- Near duplicates in-project (best-effort) must block with a “Keep both / Replace existing” prompt:
  - Detection for citing: after extraction returns title/authors/year, compare against existing document metadata in the ledger for likely matches.
  - If “Replace existing” is chosen: warn if prior review work is not transferable; default to Keep both.

Keep left pane structure decisions:
- Sections are collapsible in VSCode style; order: Intake → Documents → Sources → Project/Settings → Advanced.

Resizable sections (Streamlit-friendly interpretation):
- Add a per-section height slider (remembered per user/reviewer) that controls the max rendered height / number of visible rows in each section.
- This is the minimum acceptable implementation of “resizable section heights” for Streamlit.

Replace existing upload entrypoints:
- Remove/disable/redirect the existing "Upload documents" uploader and the hidden "Advanced: cited source uploads" uploader.
- They must either be removed from the left pane, moved under Advanced, or made to call the unified Intake handler.
Diagnosability (do not skip):
- Each Intake Inbox row must have a clickable status/icon area that opens a small details surface showing:
  - current stage (e.g., queued/uploaded/extracting/resolving/uploading-source/processing-source)
  - last event timestamp
  - last error text (if any)
- This details surface is required for both citing and source inbox items.
