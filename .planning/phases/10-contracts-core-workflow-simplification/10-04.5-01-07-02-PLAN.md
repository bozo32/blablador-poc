<task type="auto">
  <name>Task 2: Implement append + projection helpers for opinion events</name>
  <files>backend/spine/opinion_events.py</files>
  <action>
Create `backend/spine/opinion_events.py` mirroring the style of `backend/spine/evidence_decisions.py`, but simpler (no OCC required for v1).

Implement functions (minimum):
- `append_event(project_id, user_id, owner_uid, kind, target_key, visibility, group_id, mode, payload, idempotency_key=None) -> dict`
- `list_recent_events(project_id, owner_uid, target_key=None, kind=None, limit=20) -> list[dict]`
- `get_follow_status(project_id, owner_uid, target_key) -> dict | None` (projection = latest follow status)
- `list_follow_by_doc(project_id, owner_uid, doc_id, limit=500) -> list[dict]` (projection for rail)
- `export_events_ndjson(project_id, owner_uid=None, include_private=True) -> str` (lines of json)
- `import_events_ndjson(project_id, user_id, blob: bytes, overwrite: bool = False) -> dict` (used by plan 04)

Policy (v1):
- Treat all records as `private` by default.
- Enforce reads: owner can read their own private events; shared/public mechanics can be stubbed but must not leak private data.

Projection rules (v1):
- Follow is keyed by `target_key=citespan:{span_id}` so two separate citations in the same cite-window span are followed together when chasing.
- `get_follow_status(...)` returns the latest follow event's payload for that `target_key`.
- `list_follow_by_doc(...)` returns one row per `span_id` with:
  - `current_status` = latest status for that span's target_key
  - `sort_key` = minimum observed `citation_index` for that span (rail ordering by appearance, not click time)

Serialization:
- Return ISO timestamps (Z) and keep payload JSON stable (sort keys) like evidence_decisions.
