In `frontend/ui.py`, replace the use of `st.session_state["followed_citations"]` as the source of truth.

Target behavior:
- When rendering the rail for a doc, load followed citations from `list_follows_by_doc(...)` for the active reviewer.
- Keep ordering by citation appearance: prefer backend-provided ordering (appearance), and tie-break by `(citation_index, target_id)` if needed.
- When a citation is "followed" (including query-param intent), resolve its cite-window span id and write an opinion follow event keyed by that span:
  - resolve span id via `/spans/lookup-citation-window` (doc_id + citation_index)
  - write follow with `target_key=citespan:{span_id}` so two separate citations in the same cite-window span are followed together when chasing
  - status should remain stable (do not duplicate events if already followed unless status changes).
  - use an idempotency key to make UI retries safe, e.g. `follow:{span_id}:{status}`
- When a citation is dropped from the rail, write status `ignore` (do not delete; append-only).

Keep the local `st.session_state` list only as a transient cache for UI rendering if needed, but the backend must remain the durable source of truth.
