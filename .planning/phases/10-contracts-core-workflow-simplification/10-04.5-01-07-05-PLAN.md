<task type="auto">
  <name>Task 3: Replace session_state followed_citations with server-backed projection</name>
  <files>frontend/ui.py</files>
  <action>
In `frontend/ui.py`, replace the use of `st.session_state["followed_citations"]` as the source of truth.

Target behavior:

1. **Loading rail**: When rendering the rail for a doc:
   - Call `list_follows_by_doc(api_url, project_id, reviewer_uid, doc_id)` to get followed citations from server.
   - Convert the response to the format expected by `chase_queue_component.render()`:
     - Each entry needs: `doc_id`, `citation_index`, `target_id`
     - The backend returns `span_id` in the response - use it for follow writes.
   - Sort by backend-provided `sort_key` (or fallback to `citation_index`).

2. **Follow action** (`_follow_citation` function):
   - Resolve span_id via `resolve_span_id()` using (doc_id, citation_index, target_id).
   - Call `append_follow()` with:
     - `span_id` = resolved span_id
     - `target_key = f"citespan:{span_id}"`
     - `status = "follow"`
     - `idempotency_key = f"follow:{span_id}:{status}"` to avoid duplicates
   - On error (e.g., span not found), fall back to session_state behavior (graceful degradation).

3. **Drop action** (`_queue_drop` function):
   - First resolve span_id via `resolve_span_id()`.
   - Call `append_follow()` with:
     - `status = "ignore"`
     - `idempotency_key = f"follow:{span_id}:ignore"`
   - On error, fall back to session_state behavior.

4. **Keep session_state only as transient cache**:
   - After reading from server, populate a local cache in session_state for fast re-renders within the same Streamlit run.
   - But the server is the durable source of truth.

Implementation notes:
- Use `get_api_url()`, `get_project_id()`, and `_active_reviewer_uid()` to get required params.
- Handle errors gracefully: if the opinion API is unavailable, log a warning and fall back to session_state behavior (so the UI remains usable during dev/migration).
  </action>
