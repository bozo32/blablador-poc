# Phase 10-04.5-01-07: Reading Artifacts - Context

**Gathered:** 2026-02-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver durable, structurally clean "reading artifacts" without mutating canonical machine-owned extraction/spans.

In scope:

- Canonical cite-window spans are machine-owned; reviewer actions are opinion overlays.
- Opinion artifacts are private by default, optionally shared/public under explicit rules.
- `/spans/*` is explicitly scoped by `X-Project-Id` for authorization context.
- Opinion artifacts are exportable/importable so a user can delete a project from the server and later restore.

Out of scope:

- Elevated-authority editing of canonical objects (future).
- Cross-institution chase that returns candidate spans without full documents (noted as deferred).

</domain>

<decisions>
## Implementation Decisions

### Privacy + Sharing (Opinion Layer)
- **Default:** all opinion artifacts are `private`.
- **Visibilities:** `private | shared | public`.
- **Public audience:** any authenticated platform user (not world). Public is **link-only** (not globally searchable).
- **Identity on public:** `reviewer_uid` is visible (recognition + sanctions).
- **Admin access (GDPR posture):** project admins can manage groups/membership but cannot read private artifacts unless explicitly shared.
- **System owner access:** can export/analyze `shared+public` only; private remains inaccessible.
- **No aggregates from private:** do not show anonymous counts/derived signals from private artifacts.
- **Group model:**
  - any project member can create groups
  - group owner manages membership
  - invitations require acceptance
  - artifacts can be shared to **multiple groups**
  - per-artifact group permission toggle: read-only vs read/write
  - group write edits are recorded as **append-only events** with the editor as author (no overwrites)
- **Visibility changes:** allowed by flipping visibility on the same artifact; keep an owner-only history trail.
- **Public deletion:** once something is made public, it cannot be deleted (policy). (Visibility can still be flipped back to private.)
- **Graph validation/votes:** always project-visible (not private), because they affect shared truth.
- **Codes/tags:** follow the visibility of the annotation artifact that carries them.

### Opinion Artifact Model (Schema + Contracts)
- **Storage model:** append-only events + projections (event log is source of truth).
- **Single table:** one opinion-event system using `target_key` (optimize later with projections/read models).
- **Targeting:** `target_key` is the primary join handle; do not embed project in the key (project_id is a column).
- **Kinds:** start with a small fixed set and extend later:
  - `follow` (status in payload)
  - `annotation` (notes/highlights/codes)
  - `visibility_change`
  - `delete` (tombstone)
- **Follow status values (v1):** `follow | ignore | complete` (single status field in payload).
- **Robust identifiers in payload for cite-window follow:** store `span_id` plus `(doc_id, citation_index, target_id)`.
- **Cite-window grouping:** follow/chase is keyed to the cite-window `span_id` so multiple citations within the same cite-window are followed together.
- **Stable artifact ids (for editable notes/highlights):** notes/highlights have a stable `artifact_id` separate from event ids.
  - Convention: user-owned artifact ids embed owner, e.g. `ann:{owner_uid}:{uuid}`.
  - Follow/triage remains key-based (no artifact_id required).
- **Multi-target annotations:** allowed, but require a **primary** target_key plus `related_targets` list.
- **Idempotency:** optional but recommended; client can send `idempotency_key` per write; no OCC/409 in v1.
- **Read APIs required in v1:**
  - list-by-doc (doc-ordered when possible)
  - list-by-target
  - both support kind filters
  - responses return current projection + `recent_events` (default N=10)
- **UX note (history display intent):** numeric states get icons; event history is shown as expandable stacks (hover/click -> full text), consistent with cite-span history UI.
- **Codebooks:** default is a private per-user codebook; store codebook CRUD in the same opinion-event table.

### Export/Import Rules (User-controlled restore)
- **Export contents:** include only opinion artifacts the exporter is allowed to read (their private + readable shared/public).
- **Import ownership:** private artifacts only rehydrate for the same `reviewer_uid`.
- **Import target:** import is only supported into an **empty** project (restore semantics).
- **Packaging:** single zip with separate ndjson files (canonical vs opinion) + metadata.
- **Preserve ACL:** import/export preserves visibility + ACL exactly.
- **Preserve ids:** preserve opinion event ids (restore into empty project).
- **Missing identities:** import creates placeholder users/groups when referenced identities are missing.
- **Deletion:** deleting a project from the server hard-deletes private/non-exposed artifacts immediately.
- **Encryption:** no client-side encryption required for the POC; design should allow later encryption as its own phase.

### Canonical Spans + Project Scoping
- **Canonical is global:** machine-owned canonical objects (works/ingests/spans) are globally deduplicated across the whole DB.
  - On ingest: if a PDF matches an existing canonical work, link the project to the existing work.
  - If identity match is ambiguous: ask user to decide the identity (policy decision; UX to be designed elsewhere).
  - Canonical extraction artifacts (body/citations/spans) are shared and strictly global; no project forks in this phase.
- **Project linkage gates access:** even with global canonical storage, a user can only access canonical docs/spans if they are linked into their project.
  - If canonical exists but is not linked into your project, `/spans/*` behaves like not-found (404).
- **`/spans/*` scoping:** always require `X-Project-Id` as the authZ/workspace context.
  - Missing header returns 400.
- **Canonical cite-window spans creation:** automatic as part of extract/resolve.
- **Canonical stability:** a stable semantic key must exist across re-extract improvements; `span_id` may change and the index can remap.
- **Canonical visibility:** canonical objects have their own visibility setting; public annotations that include quotes assume canonical visibility is compatible.

</decisions>

<specifics>
## Specific Ideas

- Reading UX intent: citation-chip click pushes the cite-window into a right-rail collection ordered by appearance; clicking rail items navigates back to the cite-window context.
- Opinion provenance UI: iconography for fast numeric/status states; expandable "stack" UI to inspect history/details.

</specifics>

<deferred>
## Deferred Ideas

- Cross-institution chasing: querying an external corpus for candidate spans without returning full document text (copyright-safe snippet model).
- Elevated-authority edits to canonical artifacts (curation/fork/merge mechanics).
- Client-side encryption of private exports (stronger GDPR posture) as a separate phase.

</deferred>
