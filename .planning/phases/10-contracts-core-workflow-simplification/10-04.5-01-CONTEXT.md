# Phase 10-04.5-01: Intake (Unified PDF Drop) - Context

**Gathered:** 2026-02-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Unify the user-facing “drop a PDF” action into a single Intake stage that routes PDFs into either:

- `citing` documents (ingest -> extract -> resolve)
- `source` PDFs for evidence (attachments pipeline -> promote-ingest -> assign via clone)

This phase also removes web-deployment blockers in Intake (no backend dependence on UI-local file paths) and makes outcomes visible and diagnosable in the left pane.

</domain>

<decisions>
## Implementation Decisions

### Classification + Prompts
- Intake should **auto-classify** after a lightweight initial pass (metadata/bibliography/citation signals); if that fails, show an explicit `?` decision state.
- Unknown intent is resolved via a **clickable `?`** that opens a context menu.
- Ambiguous prompt: **Citing vs Source**, with **optional “attach now”** when a citing doc/target context exists.
- Citing docs: **auto-run extract + resolve** after ingest.
- User can **override classification per file**.
- Mixed batches are allowed: a single drop can contain both citing and source PDFs.
- Unknown items are **held in an Intake Inbox** until the user decides (no downstream work).
- Processing uses an **animated icon (“bicycle”/spinner)**; clicking reveals **stage + last event + error**.
- Per-document chip semantics: keep the existing **stacked superscript/subscript** visual.
- Those chip numbers represent **cites / cited-by** (outgoing/incoming) by default.

### Source Inbox + Scope
- Source Inbox is **project-shared** (not private per user).
- Default view shows **Unassigned + Matched** sources.
- After first successful assignment, a source stays available (do not auto-archive).
- A single source PDF can be reused across multiple targets/references.
- Display label:
  - Before promotion: **truncated filename**
  - After promote-ingest: **Lastname (year) TruncatedTitle** (title truncated ~15 chars)
  - If label collisions occur: append a **short hash**.
- Actions available per source item: **Archive / Unarchive**.
- Errors are visible in a **collapsible Errors section** with **red X** status icon.
- Status iconography: icon + color per state (Matched green check, Processing animated, Unknown `?`, Error red X).
- Sup/subscript metric meaning should be a **setting** (default remains cites/cited-by); alternatives include citespans/claimspans/work usage.

### Dropzone UX + Left Pane Structure
- Unified “Drop PDFs” control lives at the **top of the left pane**.
- After drop, show an **Intake Inbox list** with per-file state icons and actions.
- Left pane should be organized VSCode-style: **collapsible sections** with chevrons (e.g., `>` / `v`).
- Left pane sections should be **resizable in height** (allocate space per section).
- Section order: **Intake → Documents → Sources → Project/Settings**.
- Default expanded: **Intake + Documents**.
- Legacy/rare actions (CSV+TEI import, exports/imports, etc.) belong in a bottom **Advanced** section (collapsed by default).

### Duplicates + Idempotency
- Exact duplicate (same bytes) drop: **no-op with message**, optionally focus the existing item.
- Citing duplicates: create a **new DocumentVersion under the same Work**.
- Source duplicates: **reuse existing global source** (placements via clone).
- Near-duplicate (same title/authors, different bytes): **block and require confirmation**.
- Near-duplicate scope: **within project**.
- Near-duplicate prompt offers: **Keep both** or **Replace existing**.
- Replace existing citing doc requires a **transferability check**:
  - If prior review work is transferable: allow replace.
  - If not: warn that prior work would be lost; default to keeping both.
- Replace existing source PDF does **not** rewrite history; prior placements/clones remain pointing to the old source.

### Claude's Discretion
- Exact heuristics used for auto-classification (within the “auto-classify then ask” policy).
- The precise UI copy for status details and duplicate prompts.
- The visual design of the animated processing icon (so long as it is distinct and clickable).

</decisions>

<specifics>
## Specific Ideas

- Use an animated “bicycle” icon for in-flight processing; clicking shows the true backend processing state.
- Keep the existing superscript/subscript stacked-number visual; default meaning is cites/cited-by.
- Source display label should become citation-like only after promotion to an ingested Work.
- Left pane should feel like VSCode: collapsible, resizable sections.

</specifics>

<deferred>
## Deferred Ideas

- Full non-Streamlit UI rebuild / new web UI stack (explicitly out of scope for 10-04.5-01; belongs in a later phase once the spine protocol is boring and stable).
- “Hundreds of concurrent users” production readiness work (auth, tenancy, quotas, infra) beyond the spine-first correctness captured here.

</deferred>
