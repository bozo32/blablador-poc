## Purpose

Provide an explicit route policy inventory for `backend/main.py` without changing runtime behavior.

Each endpoint is classified in the JSON snapshot with:

- `current_scope_class` (`admin-dev`, `fallback`, `reviewer-scoped`, `unscoped`)
- `target_policy` (`scoped-required`, `global-read`, `admin/dev`)

## Classification Rules Used

### Current scope class

- `admin-dev`: route path starts with `/dev`, `/maintenance`, `/background`, or `/scope/observability`
- `fallback`: function contains explicit default scope signals (e.g., `DEFAULT_PROJECT_ID`, `DEFAULT_USER_ID`, reviewer default)
- `reviewer-scoped`: endpoint uses reviewer/user identity params but no project scope signal
- `unscoped`: no explicit project or reviewer scope signals

### Target policy

- `admin/dev`: admin or operational routes
- `global-read`: GET routes with no project/user scope signals
- `scoped-required`: all remaining routes (including writes and scoped reads)
