# 10-04.5-02 UID+Project Scope Stitch Checklist

Created: 2026-03-01
Status: draft

## Objective

Make `uid + project_id` mandatory before any activity read/write, and remove all silent fallback behavior to `default/local`.

Hard invariant:

- No stateful request executes without both user and project scope.
- No endpoint silently falls back to `DEFAULT_PROJECT_ID` or `DEFAULT_USER_ID`.
- UI cannot perform activity actions until scope is explicitly selected/applied.

## Scope Lock Contract (Target)

Required headers on scoped endpoints:

- `X-User-Id`
- `X-Project-Id`

Validation order:

1. Auth/session validity (if enabled in deployment)
2. Header presence and format
3. User membership/authorization for selected project
4. Resource-level visibility checks (public/selectable/private semantics)

Fail-closed behavior:

- Missing `X-User-Id` -> `422`
- Missing `X-Project-Id` -> `422`
- User not allowed in project -> `403`
- Visibility denies operation -> `403`

## Execution Checklist (Mapped to Files/Endpoints)

### Phase 0: Guardrail Hotfix (backend-first)

1. Add one canonical scope guard helper and use it everywhere for scoped activity routes.
   - file: `backend/main.py`
   - current anti-patterns to remove:
     - `str(x_project_id or "").strip() or str(app_settings.DEFAULT_PROJECT_ID)`
     - `str(reviewer_uid or "default").strip() or "default"`
     - `user_id = str(app_settings.DEFAULT_USER_ID)` for request actor identity

2. Enforce scope on currently strict routes and convert fallback routes to strict.
   - strict examples already in place: `/ingest`, `/ledger`, `/attachments/upload`, `/opinions/*`
   - fallback examples to convert: `/project`, `/graph/resolve-references`, `/ingest/*/(extract|resolve|resolution|body)`

3. Enumerate unscoped routes and classify each as:
   - `scoped-required` (must enforce headers)
   - `global-read` (allowed unscoped by design)
   - `admin/dev` (explicitly gated)
   - primary file: `backend/main.py`

4. Standardize error payload shape for scope failures.
   - file: `backend/main.py`
   - return stable machine-readable error codes for missing headers and membership failures

### Phase 1: User/Project Domain Contract

1. Add user-project membership source of truth.
   - likely files: `backend/db/migrate.py`, new spine helper under `backend/spine/`
   - needed capabilities:
     - list projects for user
     - create project for user
     - set/get user active project

2. Extend project APIs to be user-aware and list-capable.
   - current files: `backend/main.py` (`/project` only), `backend/spine/project_meta.py`
   - add endpoints for project list/create/select (or equivalent)

3. Keep `project_meta` as per-project metadata, but do not use it as membership authority.
   - file: `backend/spine/project_meta.py`

### Phase 2: Frontend Scope UX Lock

1. Make scope explicit and sticky in UI before actions.
   - file: `frontend/ui.py`
   - required UX:
     - user id and project picker visible
     - project can be selected from list or created
     - explicit `Apply`/`Switch` action
     - disable activity controls until applied

2. Ensure all API clients send required scope headers.
   - files:
     - `frontend/project_api.py` (currently sends no `X-Project-Id`)
     - `frontend/ingestion_api.py` (`_ingest_headers` returns `{}` when missing)
     - `frontend/ledger_api.py` (`_headers` returns `{}` when missing)
     - `frontend/graph_api.py` (`_project_headers` returns `{}` when missing)
     - `frontend/opinion_api.py` (`_opinion_headers` returns `{}` when missing)

3. Remove auto-default scope on reload.
   - file: `frontend/ui.py`
   - do not silently restore `default` in new sessions

### Phase 3: Visibility Policy Stitch

1. Preserve `visibility/group_id/mode` in opinion events.
   - files: `backend/spine/opinion_events.py`, `backend/db/migrate.py`

2. Enforce visibility at read/write boundaries consistently.
   - file: `backend/main.py`
   - current state: visibility is stored, partially used for export filtering, not globally enforced as ACL

3. Define and document exact semantics for:
   - `public`
   - `selectable` (group/member-shared)
   - `private`

## Acceptance Criteria

1. Reload/new browser retains selected user+project scope by backend truth, not local defaults.
2. Any request without required scope fails closed.
3. No new writes occur under `default/local` during normal UI workflow.
4. Project list and create/select flow works end-to-end for user-bound projects.
5. Visibility semantics are consistently enforced on opinion reads/writes.

## Smoke Matrix

## Staged Functional Checks

Yes, staged checks are sensible and recommended. Use this gate after each PR.

Stage A: Contract checks (unit/API)

- Verify missing `X-User-Id` -> `422` on strict routes.
- Verify missing `X-Project-Id` -> `422` on strict routes.
- Verify malformed ids -> `422` with stable code.

Stage B: Authorization checks

- Valid user not in project -> `403`.
- Valid user in project -> success.
- Optional: token-subject mismatch -> `401`.

Stage C: Cross-scope isolation checks

- Create project A and B; ingest/upload in A.
- Confirm A data cannot be listed/read in B for same user unless explicitly duplicated.
- Confirm user B cannot read user A private reviewer state.

Stage D: UI workflow checks

- Open fresh browser: no activity panes enabled until scope is selected/applied.
- Select project A, upload doc, refresh browser: still in A, same docs shown.
- Switch to B and refresh: A docs no longer shown.

Stage E: Regression checks (existing critical flows)

- Hicks-style place-reference resolution still works.
- Placed documents refresh reflects current scoped backend rows.
- Opinion follow rail still accumulates/loads in selected scope.

Stage F: Safety checks before merge

- `rg` proves no scoped handler still uses `or str(app_settings.DEFAULT_PROJECT_ID)`.
- `rg` proves no request actor assignment still uses `DEFAULT_USER_ID` in scoped writes.
- All new/updated endpoints documented with required headers and error codes.
