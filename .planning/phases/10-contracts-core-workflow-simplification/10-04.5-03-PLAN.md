# 10-04.5-03 UX Follow-up

## Objective

Close two UX blockers with the smallest safe patch set:

1. Permanent duplicate widget-key fix in chasing queue across right-rail + center co-render.
2. Phase-1 only removal of blocking upload role prompt via non-blocking auto-routing for unknown uploads.

## Scope

In scope now:

- A) Widget key namespace hardening for requested-works controls.
- B) Phase-1 intake behavior: unknown uploads auto-route without blocking, with optional override controls retained.

Out of scope now:

- B) Phase-2 unified backend intake router contract.
- B) Phase-3 full citing/source pipeline unification and migration.

## Patch Plan

### A) Permanent duplicate widget-key fix (smallest safe patch)

Problem summary:

- `render_requested_works_queue()` keys are currently scoped by `workflow::{selected_claim_id}`.
- The same selected claim can render in two panels in one Streamlit pass (rail + center tab), causing duplicate keys.

Implementation:

1. Update requested-works scope composition to include parent panel instance scope.
2. Keep all existing widget IDs and behavior unchanged except key prefix uniqueness.

Files:

- `frontend/components/chasing_panel.py`
  - change `scope` passed to `chase_queue_component.render_requested_works_queue(...)`
  - from: `workflow::{selected_claim_id}`
  - to: `{scope}::workflow::{selected_claim_id}`

Why this is the smallest safe patch:

- Single-line behavior change at the callsite that already has panel scope context.
- No queue data model changes.
- No backend/API changes.

### B) Phase-1 non-blocking upload role routing (low-risk only)

Phase-1 target:

- Unknown uploads do not block on manual role selection.
- Unknown uploads auto-route immediately.
- Optional override controls remain available (non-blocking).
- Default route preserves spine-first correctness.

Phase-1 implementation policy:

- Default unknown uploads to citing pipeline (`/ingest` path) for correctness-first behavior.
- Keep explicit override controls in Intake row (route as source / attach now when context exists).
- Surface that the route was auto-chosen from unknown intent.

Files:

- `frontend/ui.py`
  - `_handle_drop()` in `render_intake_panel(...)`
    - for unknown intent, do not set `awaiting-intent`
    - enqueue immediately via citing route
    - record provenance fields (`intent_guess`, `auto_routed`, `override_available`) for UI clarity
  - `render_intake_panel(...)` row controls
    - keep override buttons visible for auto-routed-from-unknown items
    - relabel copy to indicate optional override (not required to continue)
  - empty-state caption copy
    - remove message that unknown items wait for manual selection
  - `_intake_refresh_item_status(...)`
    - ensure status tracking follows the active routed intent for auto-routed unknowns

Guardrails:

- No backend contract change in Phase-1.
- No deletion of existing source-routing controls.
- No migration of old intake records.
