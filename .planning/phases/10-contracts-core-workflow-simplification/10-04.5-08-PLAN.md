# 10-04.5-08 Scope/Workflow Regression Fixes (Minimal + Safe)

## Goal

Implement minimal, low-risk fixes for newly-debugged scope/workflow regressions while preserving strict scope and membership guarantees end-to-end.

## Non-Negotiable Constraints

- Do not relax strict scope requirements (`X-Project-Id`, `X-User-Id`, membership-checked project selection).
- Do not add fallback behavior that silently broadens access or cross-project visibility.
- Keep changes additive/surgical; no broad workflow redesign in this patch set.

## Task A - User discovery list robustness for scope selector

### Target files

1. `frontend/ui.py`
   - Harden user-discovery parsing in `render_scope_selector_block()` so malformed `/projects/users` payloads do not degrade the selector into an unusable state.
   - Normalize and dedupe IDs defensively (`None`, non-list, mixed-type rows, blank strings).
   - Preserve typed draft user (`scope_new_uid`) and currently applied user as selectable values even when discovery fetch fails.

2. `frontend/project_api.py`
   - Keep transport behavior unchanged, but ensure `list_users()` call-site assumptions are matched by robust caller-side shape checks.

### Tests

1. `tests/test_frontend_scope_selector_lock.py`
   - Add coverage for bootstrap/discovery fallback behavior where applied/draft user remains usable when discovery payload is absent or malformed.

2. `tests/test_project_api_scope_headers.py`
   - Add a malformed users payload case (non-dict / missing `users`) and confirm scope UI-facing logic tolerates it without scope guard bypasses.

### Acceptance checks

- Scope selector continues rendering when `/projects/users` fails or returns malformed JSON.
- Draft/applied user context is preserved; user can still proceed with explicit IDs.
- No silent fallback to an unscoped or auto-selected identity.

## Task B - Prevent implicit project auto-creation unless explicit new-project intent

### Target files

1. `frontend/ui.py`
   - In `render_scope_selector_block()` Apply/Switch flow, gate `project_api.create_project(...)` behind explicit new-project intent only.
   - Track explicit intent from the `+ New project...` path (or equivalent draft marker) and do not auto-create on generic select failures.
   - Preserve existing behavior for explicit new-project submissions.

### Tests

1. `tests/test_frontend_scope_selector_lock.py`
   - Add a regression case: failed `select_project()` for a non-member/nonexistent project does not create a project unless explicit new-project intent is set.
   - Add a positive case: explicit new-project path still creates then applies successfully.

2. `tests/test_project_membership_api.py`
   - Keep membership 403 behavior covered as the expected backend signal consumed by UI (no contract relaxation).

### Acceptance checks

- Selecting an invalid/unowned project no longer implicitly creates it.
- Explicit `+ New project...` creation still works and applies scope on success.
- Membership failures remain hard failures with user-visible warning (no bypass).

## Task C - Dedupe unknown-intent upload notes

### Target files

1. `frontend/ui.py`
   - Remove duplicate unknown-intent messaging so each intake row shows one clear note, not repeated captions conveying the same content.
   - Keep policy text intact: unknown intent remains auto-routed to citing metadata-first flow.

### Tests

1. `tests/test_intake_auto_route_phase1.py`
   - Add assertion that unknown-intent auto-route hint appears once per item render.
   - Preserve existing checks for `auto_routed=True`, `routed_intent="citing"`, and no route-choice controls.

### Acceptance checks

- Unknown-intent intake rows display a single concise guidance note.
- Behavior stays metadata-first and non-blocking; only copy duplication is removed.

## Task D - Refresh/invalidate ledger counts after successful auto-place

### Target files

1. `frontend/ui.py`
   - In the successful `Auto-place cited source` path, invalidate ledger-derived cache/session keys before `_rerun()` (at minimum `ledger_payload`).
   - If needed, centralize cache invalidation in a tiny helper shared by scope switch and auto-place success paths.

### Tests

1. `tests/test_frontend_scope_selector_lock.py`
   - Add focused session-state invalidation regression coverage for successful auto-place path (or helper) so stale `0/0` counters do not persist.

2. `tests/test_projection_scope_consistency_api.py`
   - Keep API auto-place contract green; this patch should only change UI cache freshness behavior.

### Acceptance checks

- After successful auto-place, placed-doc/edge counters refresh on rerun instead of sticking at stale `0/0`.
- No backend contract changes required for this refresh.

## Task E - Scope bootstrap failure handling (no silent gated mode + no stale center context)

### Target files

1. `frontend/ui.py`
   - Replace silent bootstrap exception swallow in query-param scope bootstrap (`except Exception: pass`) with explicit session-state error marker and user-facing warning/caption.
   - On bootstrap failure or unapplied-scope gate, clear stale center-pane context keys that can misrepresent active scope (`selected_doc_id`, `active_document`, citation context cache/navigation context as needed).
   - Ensure gate copy explains why workspace is locked and what action unblocks it.

2. `frontend/scope_lock.py`
   - Optionally return richer sync result/status (or helper) so caller can distinguish "no user provided" vs "backend/session fetch failed" without changing strict behavior.

### Tests

1. `tests/test_frontend_scope_selector_lock.py`
   - Add coverage for failed `sync_from_backend()` path: no implicit apply, failure signal is preserved, and stale applied scope is not fabricated.

2. `tests/test_intake_auto_route_phase1.py` (if minimal UI stub reuse is easiest)
   - Add a tiny gating-state regression asserting stale center-selection keys are cleared when scope is unapplied after bootstrap failure.

### Acceptance checks

- Bootstrap failures are visible to the reviewer (not silently swallowed).
- Workspace remains correctly gated until explicit valid Apply/Switch.
- Stale center-pane context from prior scope is cleared, preventing misleading document/citation state.

## Manual Verification Checklist

1. Break `/projects/users` response shape (or force failure) and confirm scope selector still allows explicit user/project draft entry without crashing.
2. Attempt Apply with a non-member/nonexistent project chosen from non-new-project path; confirm no project is auto-created.
3. Use explicit `+ New project...` path and confirm project creation + scope apply still succeed.
4. Upload an unknown-intent PDF and confirm only one unknown-intent guidance note is shown.
5. Trigger successful auto-place and confirm ledger counters refresh (no persistent stale `0/0`).
6. Force scope bootstrap failure (bad query-param scope, backend refusal) and confirm visible failure message + cleared stale center-pane context.

## Rollback

- Revert UI-only guard/invalidation/message changes in `frontend/ui.py` and optional `frontend/scope_lock.py`.
- Keep backend strict membership/scope contracts untouched; rollback does not require API schema changes.
