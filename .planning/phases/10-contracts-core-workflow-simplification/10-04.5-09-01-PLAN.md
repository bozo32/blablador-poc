# 10-04.5-09-01 Backend Retrieval Contract Strictification

## Objective

Make retrieval dossier endpoint behavior strictly scope-bound, matching existing scoped endpoint policy: require explicit user/project scope on request, resolve scope centrally, and remove default-project binding from retrieval load path.

## Target Files

- `backend/main.py`
- `backend/reference_retrieval.py`
- `tests/test_reference_retrieval.py`
- `tests/test_projection_scope_consistency_api.py` (or nearest scoped API contract suite)

## Phase Tasks

### Task 1 - Strict headers on retrieval endpoint

Implementation:

1. Update `GET /references/{doc_id}/{reference_id}/retrieval` to require:
   - `X-Project-Id`
   - `X-User-Id`
2. Resolve scope via existing canonical scope helper (`_resolve_scope_observability` path) with fail-closed settings:
   - `require_project=True`
   - `require_user=True`
   - `allow_dev_project_default=False` for this retrieval route
3. Preserve current HTTP mapping for missing document in scoped project (`404`), but separate this from missing-scope failures.

Dependency:

- Existing strict scope helper behavior in `backend/main.py`.

Verification gate:

- Missing scope headers return strict validation failure.
- Valid scope reaches retrieval builder with resolved project id.

Rollback:

- Revert endpoint signature and scope helper wiring in a single commit if compatibility failure is discovered.

### Task 2 - Remove default project binding in retrieval builder path

Implementation:

1. Change retrieval API to explicit project parameter:
   - `build_retrieval_dossier(doc_id, reference_id, *, project_id)`
2. Change internal loader to explicit project parameter:
   - `_load_document(doc_id, *, project_id)`
3. Ensure `build_ingested_document_from_spine(..., project_id=project_id)` uses supplied scope value only.
4. Remove request-time dependency on `settings.DEFAULT_PROJECT_ID` for this scoped path.

Dependency:

- Task 1 scope resolution output.

Verification gate:

- Retrieval succeeds for doc present in scoped non-default project.
- Retrieval returns `404` for same doc id in wrong project (no existence leak).

Rollback:

- Revert function signature changes and callsite plumbing together to prevent half-updated state.

### Task 3 - Backend regression tests for scope contract

Implementation:

1. Add/extend tests for retrieval endpoint contract:
   - missing `X-Project-Id` fails closed
   - missing `X-User-Id` fails closed
   - valid headers + correct project returns dossier
   - valid headers + wrong project returns not found/denied behavior per current policy
2. Add unit coverage for retrieval builder to prove supplied `project_id` is used end-to-end.

Dependency:

- Task 1 and Task 2 implementation landed.

Verification gate:

- New tests fail on old behavior, pass on strict behavior.

Rollback:

- Keep tests even if temporary rollback is required; mark as expected-fail only if release emergency requires it.

## Acceptance Criteria

1. Retrieval endpoint is no longer unscoped.
2. Retrieval builder no longer binds to default project for scoped flow.
3. Non-default project placed-document retrieval works when scope headers match project membership.
4. Cross-project retrieval attempts do not leak data.

## Validation Commands

1. `./.venv/bin/pytest tests/test_reference_retrieval.py`
2. `./.venv/bin/pytest tests/test_projection_scope_consistency_api.py`
3. `./.venv/bin/pytest tests/test_frontend_scope_client_guards.py` (for shared scope error expectations)

## Risks and Mitigations

- Risk: legacy callers break after header requirement.
  - Mitigation: Phase 2 frontend propagation is mandatory before release gate.
- Risk: response code mismatch vs existing client assumptions.
  - Mitigation: lock expected status behavior in tests during this phase.
