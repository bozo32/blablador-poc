# 10-04.5-09 Retrieval Scope Regression Fix Plan

## Goal

Eliminate the placed-document retrieval regression by aligning retrieval instructions flow to the strict scope contract already established in Phase 10-04.5: no unscoped stateful reads, no implicit default-project fallback, and no cross-scope cache bleed.

## Scope of Change

- Backend retrieval endpoint contract and loader project resolution.
- Frontend retrieval caller header propagation.
- Retrieval cache key scoping and scope-switch invalidation.
- Regression test coverage for contract, cache, and end-to-end behavior.

## Non-Negotiable Constraints

- Do not relax strict scope requirements (`X-Project-Id`, `X-User-Id`) for retrieval flows.
- Do not reintroduce `DEFAULT_PROJECT_ID` fallback for scoped retrieval paths.
- Fail closed for missing/invalid scope; no silent broadening of access.

## Phased Execution

### Phase 0 - Contract lock and blast-radius guard

Deliverables:

1. Confirm retrieval endpoint classification is `scoped-required` in plan docs.
2. Freeze expected request/response error semantics for missing scope headers.
3. Record target caller list that must propagate headers before merge.

Dependencies:

- Existing strict scope contracts from `10-04.5-01-07-01-PLAN.md` and checklist invariants.

Verification gate:

- Gate 0 passes when planned backend/frontend targets are explicit and no fallback exception is documented.

Rollback note:

- Documentation-only phase; no runtime rollback required.

### Phase 1 - Backend contract strictification

Execute: `10-04.5-09-01-PLAN.md`

Dependencies:

- Gate 0 completed.

Verification gate:

- Retrieval endpoint rejects missing scope headers and resolves documents only within supplied project scope.

Rollback note:

- Revert retrieval endpoint/header enforcement and project_id-plumbed retrieval builder together (single backend rollback unit).

### Phase 2 - Frontend propagation and cache hardening

Execute: `10-04.5-09-02-PLAN.md`

Dependencies:

- Phase 1 merged or present in branch.

Verification gate:

- All retrieval callers send required headers; cache keys are scope-aware; scope switch clears retrieval cache.

Rollback note:

- Revert frontend caller signatures + retrieval cache key changes as one unit if UI breakage occurs.

### Phase 3 - Regression gates and rollout decision

Execute: `10-04.5-09-03-PLAN.md`

Dependencies:

- Phase 1 and Phase 2 complete.

Verification gate:

- Automated tests + manual cross-project smoke matrix all green.

Rollback note:

- If any gate fails, stop release and roll back by phase boundary (Phase 2 first, then Phase 1 if needed).

## Cross-Plan Dependencies

- `10-04.5-09-02-PLAN.md` requires backend API signature from `10-04.5-09-01-PLAN.md`.
- `10-04.5-09-03-PLAN.md` requires final endpoint/client/cache behavior from both implementation plans.

## Acceptance Criteria

1. Retrieval instructions for a placed document succeed in non-default project scope when document exists in that project.
2. Missing scope headers for retrieval path fail closed with stable error behavior.
3. Retrieval responses are isolated per `(user_id, project_id, doc_id, reference_id)` in frontend cache behavior.
4. Scope switch cannot surface stale retrieval dossier from previous scope.
5. Regression tests prevent reintroduction of unscoped retrieval contract and cache leakage.
