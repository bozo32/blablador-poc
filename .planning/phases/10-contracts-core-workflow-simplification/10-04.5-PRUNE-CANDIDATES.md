## 10-04.5-01-11 (UID+Project Scope Lock + Combing Pass)

Normal combing protocol for this pass:

1. Route comb (`backend/main.py`)
   - classify every endpoint as strict/fallback/unscoped
   - mark intended target class: `scoped-required`, `global-read`, or `admin/dev`

2. Fallback comb (`backend/**/*.py`, `frontend/**/*.py`)
   - grep and review:
     - `or str(app_settings.DEFAULT_PROJECT_ID)`
     - `DEFAULT_USER_ID`
     - reviewer defaults (`"default"`)
     - client helpers that return empty headers when scope missing

3. Policy comb (visibility)
   - verify `public/selectable/private` semantics are not only stored but enforced at read/write boundaries

4. Every finding from combing gets a prune/gate/remove entry below.

Candidates captured from this combing pass:

1. `backend/main.py` - endpoint-level fallback to `DEFAULT_PROJECT_ID`
   - why: silent fallback causes cross-project drift on reload/new session; violates strict scope lock
   - replaced_by: canonical strict scope guard requiring `X-Project-Id`
   - safe_to_delete_after: all scoped routes fail-closed and frontend always supplies scope
   - confidence: high
   - status_now: active across multiple non-upload routes (`/project`, parts of `/ingest/*`, `/graph/resolve-references`, spine helper routes)

2. `backend/main.py` - request actor fallback to `DEFAULT_USER_ID`
   - why: activity is attributed to synthetic local user; violates uid-required invariant
   - replaced_by: required request user identity (`X-User-Id` or equivalent auth principal)
   - safe_to_delete_after: membership-aware user/project contract is in place
   - confidence: high
   - status_now: active in many write paths

3. `backend/main.py` - optional reviewer identity defaults (`reviewer_uid="default"`)
   - why: private reviewer state can silently coalesce into shared default bucket
   - replaced_by: explicit reviewer uid + authorization check
   - safe_to_delete_after: all reviewer-scoped endpoints reject missing reviewer identity
   - confidence: high
   - status_now: widespread

4. `frontend/project_api.py` - unscoped `/project` requests (no `X-Project-Id` header)
   - why: project meta fetch/put/export/import can bind to backend default scope unintentionally
   - replaced_by: project API client that always includes active scope headers and fails early if unset

   - status_now: active
