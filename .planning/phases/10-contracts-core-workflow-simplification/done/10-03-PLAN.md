  <name>Task 2: Implement Surfing selection contract + action-first routing (Go Read / Go Chase / Expand / Retrieval)</name>
  <files>frontend/nav_api.py, frontend/components/live_surfing_panel.py, frontend/ui.py</files>
  <action>
Turn Surfing into a deterministic controller that routes into Reading/Chasing only on explicit action clicks.

1) Add `frontend/nav_api.py`.
- Implement tiny request wrappers:
   - `get_nav_graph(api_url, *, reviewer_uid, focus_type, focus_id, show_claimspans) -> dict`
   - `get_work_contexts(api_url, *, work_id, reviewer_uid) -> dict`
   - `get_reference_retrieval(api_url, *, doc_id, reference_id) -> dict`
- Keep timeouts conservative and error messages short; return `{}` on empty body.

2) Update `frontend/components/live_surfing_panel.py` to use the seq-gated interaction pattern.
- Treat Cytoscape as renderer + event emitter only.
- Session state (names can follow existing `surf_live_*`):
  - `graph_nav_selection` dict `{type, id, state?, meta?}`
  - `graph_nav_last_event_seq_by_key` mapping keyed by cytoscape component key
  - `graph_nav_focus` (what graph is currently centered on)
  - `graph_nav_show_claimspans` toggle (maps to locked density toggle)
- Event handling:
  - Read component value `{type,id,action,seq,...}`.
  - Process only when `seq` is strictly greater than the stored last seq for that component key.
  - On new selection, set `graph_nav_selection` only; do NOT mutate routing keys.

3) Implement the action-first mini panel (popover substitute) in Surfing.
- When a selection exists, render a compact "Selection" panel with:
  - One-line label + state badge.
  - Buttons:
    - `Go Read` (default)
    - `Go Chase`
    - `Open PDF` when a PDF exists for that selection's work/doc
     - `Expand` for cited work nodes (one hop)
     - `Request` / `Cancel request` for missing works (no auto-download)
  - Ambiguity handling (locked):
   - If a selection maps to multiple citing contexts, show a chooser list inside the panel.
   - Use `/nav/works/{work_id}/contexts` for the rows.
   - For the case "cited work referenced in multiple citing contexts": always ask; do not remember last choice.

3.1) Retrieval wiring (missing/unavailable works must be actionable).
- Preconditions: The selected work node MUST have a citing context chosen (because retrieval is keyed by `{citing_doc_id, reference_id}`).
- In the selection panel, when `state in {missing, blocked, requested}` (or any non-available state you choose to map):
  - Show a `Retrieval` section above routing actions.
  - If no citing context is chosen yet (ambiguous or no contexts loaded), render a short prompt: "Pick a citing context to view retrieval details".
  - Once a context is chosen (from `/nav/works/{work_id}/contexts`), call `get_reference_retrieval(api_url, doc_id=citing_doc_id, reference_id=reference_id)` and render:
    - `canonical_citation` (text)
    - `doi` and `primary_url` as clickable links when present
    - `manual_instructions` (multiline) when present
    - A short list of `sources[]` with label + url (when present)
- Keep this as pure display + request intent; do not implement auto-download.

4) Routing semantics (locked):
- Implement routing by mutating existing session keys + tab key (no new router):
  - For Reading (Go Read/Open PDF): set `WORKSPACE_ACTIVE_TAB = WORKSPACE_TAB_DOCUMENT` and set citation selection keys so Reading jumps to the right context.
  - For Chasing (Go Chase): set `WORKSPACE_ACTIVE_TAB = WORKSPACE_TAB_REVIEW` and set the same citation selection keys; if a more specific cited citespan/claimspan is selected, also set any existing chasing selection keys used by `frontend/components/chasing_panel.py` (reuse patterns already present; avoid inventing parallel keys).
- After setting routing keys, call `st.rerun()`.

5) Recursive expand + persistence.
- Expand behavior:
  - Expansion is one hop per click; it should append nodes without forcing a relayout.
  - Do not bump Cytoscape `layoutNonce` on expand; keep `stableLayout=True`.
- Persistence:
  - Read-modify-write `project_meta.graph_settings` via `frontend/project_api.get_meta()` + `frontend/project_api.put_meta()`.
  - IMPORTANT: backend patch is shallow; never send only a partial `graph_settings` dict.
  - Cap stored id lists to a reasonable size.

6) Render graph elements from backend.
- Fetch `elements` via `/nav/graph` using the current focus + show_claimspans toggle.
- Pass `selection` into `cytoscape_panel.render(selection=...)` so the highlight stays stable.
- Keep a stable `key=` for cytoscape component across reruns (avoid viewport reset);
  only bump the key or `layoutNonce` on explicit "Reset layout" action.

Constraints:
- No new JS tooling; use the vendored Cytoscape component as-is.
- Do not add edge/node annotation UX (10-04).
