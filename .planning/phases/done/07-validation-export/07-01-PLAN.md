  <name>Task 1: Implement on-disk JudgmentStore + Pydantic models (draft/final + notes + provenance)</name>
  <files>
backend/judgment_store.py
backend/schemas.py
tests/test_judgment_store.py
  </files>
  <action>
- Create `backend/judgment_store.py` mirroring the Phase 06 store pattern in `backend/evidence_selection_store.py`, but for judgments:
  - Persist one record per `claim_id` under a new directory (e.g., `data/judgments/`) using JSON files.
  - Use a file-safe id function, but avoid collisions by adding a short hash suffix (e.g., first 8 chars of sha1 of full claim_id): `{safe_claim_id}__{hash}.json`.
  - Include `_now()` (UTC ISO string) and always update `updated_at` on upsert.

- Add Pydantic models to `backend/schemas.py` (Pydantic v2 style, consistent with existing models):
  - `JudgmentVerdict = Literal["support", "contradict", "uncertain"]`
  - `JudgmentStatus = Literal["draft", "final"]`
  - `JudgmentNotes` as structured optional fields (choose a small set; recommended: `rationale`, `caveats`, `followups`).
  - `JudgmentPayload` (persisted/read model) with:
    - `claim_id: str`
    - `updated_at: str | None`
    - `status: JudgmentStatus = "draft"`
    - `verdict: JudgmentVerdict | None = None` (allowed to be None in draft)
    - `notes: JudgmentNotes | None = None`
    - Provenance fields for callout mapping + export (all optional but should be filled by the UI when available):
      - `doc_id: str | None`
      - `citation_index: int | None`
      - `target_id: str | None`
      - `sentence_id: str | None`
      - `callout: str | None`
      - `reference_id: str | None`
      - `doi: str | None`, `author: str | None`, `year: str | None`
      - `claim_text: str | None` (store a snapshot for exports)

  - `JudgmentUpsertRequest` for PUT with the same fields except `claim_id`/`updated_at` (set those server-side).

- Enforce LOCKED rules via model validation (prefer `model_validator`):
  - If `status == "final"`, then `verdict` must be one of the three verdicts (not None).
  - If `status == "draft"`, allow `verdict` to be None or a verdict.
  - Notes are always optional.
  - Keep verdict labels exactly Support/Contradict/Uncertain at the product level; store them as lowercase literals for consistency.

- Add unit tests in `tests/test_judgment_store.py`:
  - Final requires verdict (validation fails on missing verdict).
  - Draft allows missing verdict.
  - Notes are structured and optional (missing notes passes; partial notes passes).
  - Filename collision guard: two claim_ids that sanitize to the same safe id still produce distinct paths (hash suffix differs).
  </action>
  <verify>pytest -q</verify>
  <done>

  - Draft/final semantics match locked decisions.
  - Store path logic is collision-safe.

  <name>Task 2: Wire FastAPI endpoints for judgment CRUD/list and export (JSON/CSV; claim/callout shapes)</name>
  <files>

  <action>
- In `backend/judgment_store.py`, add helpers used by export:
  - `list_all()` -> list[JudgmentPayload]
  - `list_filtered(*, status: Literal["final", "draft", "all"], doc_id: str|None = None)`
  - `export_claims(*, include_drafts: bool, mode: Literal["core", "verbose"], format: Literal["json", "csv"])` returning bytes/str.
   - `export_callouts(*, include_drafts: bool, mode: Literal["core", "verbose"], format: Literal["json", "csv"])`:
     - JSON shape: an array of objects (NOT tuple-keyed), one per `(doc_id, citation_index, target_id)` group, exactly:
       - `[{doc_id, citation_index, target_id, callout, claims:[...]}]`
       - Group object fields:
         - `doc_id: str | null`, `citation_index: int | null`, `target_id: str | null`, `callout: str | null`
         - Deterministic `group.callout` selection (WARNING): compute `callout` as the first non-null `callout` among claims after sorting claims by `claim_id` ascending; if all are null/missing, set `callout=null`.
         - `claims: array` of claim-judgment objects.
       - Claim object fields:
         - `mode=core`: `{claim_id, status, verdict, claim_text}` (use null for missing optional values)
         - `mode=verbose`: include the core fields plus `{notes, sentence_id, reference_id, doi, author, year, updated_at}` (use null for missing optional values)
       - Deterministic ordering (required for stable tests/exports):
         - Groups sorted by `doc_id` asc, then `citation_index` asc, then `target_id` asc (treat null as empty string / -1 consistently).
         - Within each group, `claims` sorted by `claim_id` asc.
    - CSV shape: row-per-(callout, claim) flattened output (avoid nested dicts/arrays in cells).
  - Default export behavior (LOCKED): final-only. Implement as `include_drafts=false` default at the API layer.

- In `backend/main.py`, add endpoints (keep style consistent with existing `/claims/{claim_id}/evidence/*` endpoints):
  - `GET /claims/{claim_id}/judgment` -> return stored `JudgmentPayload` or a default payload `{claim_id, status:"draft", verdict:null, notes:null}`.
  - `PUT /claims/{claim_id}/judgment` -> validate `JudgmentUpsertRequest`, upsert, return stored `JudgmentPayload`.
  - `GET /judgments` -> list judgments (support query params `doc_id` and `include_drafts` or `status=...`).
  - `GET /judgments/export` -> returns export content with query params:
    - `shape=claim|callout` (required)
    - `format=json|csv` (default json)
    - `include_drafts=true|false` (default false)
    - `mode=core|verbose` (default core)
    - API contract (BLOCKER): return a raw downloadable payload (bytes/text) with correct `media_type` based on `format`:
      - `format=json` -> `application/json`
      - `format=csv` -> `text/csv`
      - Must NOT return a JSON envelope or `response_model`-encoded object for export (avoid FastAPI JSONResponse/Pydantic serialization here).
      - Implement with `fastapi.responses.Response` (or `StreamingResponse` if desired, not required) and set the export content directly.
      - Optional: set `Content-Disposition` with a filename; minimum requirement is that the payload is directly downloadable by Streamlit.

- Error handling:
  - 422 from Pydantic/ValidationError for invalid final payloads.
  - 404 only for truly missing resources where appropriate; `GET /claims/{claim_id}/judgment` should NOT 404.

 - Extend `tests/test_judgment_store.py` (or add additional tests in the same file) to cover:
   - Export defaults are final-only (draft records excluded unless include_drafts=true).
   - Both export shapes render deterministically with stable ordering (sort by `doc_id`, `citation_index`, `claim_id` to keep tests stable).
   - Callout export `group.callout` selection is deterministic when claims have differing `callout` values and when some/all claims omit `callout`.
   - CSV output contains expected headers and row counts for a small fixture set.
   </action>
  <verify>pytest -q</verify>
