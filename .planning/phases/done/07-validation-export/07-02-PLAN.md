- Create `frontend/judgment_api.py` modeled after `frontend/evidence_api.py`:
  - Reuse the same `_api_root()` + `_auth_headers()` pattern (copying code is acceptable here to keep modules independent).
  - Provide `get_judgment(claim_id)` calling `GET /claims/{claim_id}/judgment`.
  - Provide `put_judgment(claim_id, payload)` calling `PUT /claims/{claim_id}/judgment`.
  - Provide `list_judgments(*, doc_id: str|None = None, include_drafts: bool = False)` calling `GET /judgments`.
  - Provide `download_export(*, shape: Literal["claim","callout"], format: Literal["json","csv"]="json", include_drafts: bool=False, mode: Literal["core","verbose"]="core")` calling `GET /judgments/export` with a RAW request (use `requests.get`, not evidence_api-style JSON helpers) and returning a download-ready object:
    - Must NOT call `response.json()` (this can produce Python objects that break `st.download_button`).
    - `format=json`: return `content=response.text` (string), `mime="application/json"`.
    - `format=csv`: return `content=response.content` (bytes) OR `response.text` (string) but do not JSON-decode; `mime="text/csv"`.
    - Always return `{content: str|bytes, mime: str, filename: str}` where `filename` is deterministic from params (e.g., `judgments_{shape}_{mode}{"_with_drafts" if include_drafts else ""}.{format}`).
    - Object must be directly usable as `st.download_button(data=content, mime=mime, file_name=filename)` with no additional transformation.

- Keep error handling consistent:
  - Define `JudgmentApiError` and show toast/error via Streamlit like `EvidenceApiError` does.
  - Keep network code under `pragma: no cover` where appropriate (matching evidence_api).

<task type="auto">
  <name>Task 2: Implement session-backed JudgmentStore + unit tests for caching and callout aggregation</name>
  <files>
frontend/judgment_store.py
tests/test_judgment_frontend_store.py
  </files>
  <action>
- Create `frontend/judgment_store.py` mirroring `frontend/evidence_store.py` patterns:
  - Maintain a session root (e.g., `"_judgment_store_state"`) containing:
    - `claims: {claim_id: {judgment, stale, error}}`
    - `doc_index: {doc_id: {judgments_by_claim_id, judgments_by_callout_key}}` (optional, but support efficient callout status).
  - Provide methods:
    - `sync_judgment(claim_id, *, force=False)` -> fetch and cache judgment.
    - `save_judgment(claim_id, *, status, verdict, notes, provenance)` -> PUT and cache.
    - `sync_doc(doc_id, *, include_drafts=False, force=False)` -> list judgments for doc and cache.
    - `callout_status(doc_id, citation_index, target_id)` -> returns a small dict:
      - `validated: bool` (true only if any claim for callout has status==final and verdict set)
      - `outcome: "support"|"contradict"|"uncertain"|None` (if multiple final verdicts disagree, outcome should be `"uncertain"` for styling)
      - `claim_ids: list[str]` (for navigation)
      - Fallback matching for stored judgments missing `target_id` (required so callout indicators/export mapping don't break on legacy data):
        - Try exact key `(doc_id, citation_index, target_id)` first.
        - If no matches AND `target_id` is provided, fall back to `(doc_id, citation_index, None)`.

- Keep it dependency-light and Streamlit-safe: no new deps, session-only caching.

- Add `tests/test_judgment_frontend_store.py` using the same technique as `tests/test_evidence_store.py`:
  - Monkeypatch a stub Streamlit module (`session_state`, `toast`, etc.).
  - Provide a stub API object with `get_judgment`, `put_judgment`, `list_judgments`, `download_export`.
  - Test (treat stubs/fixtures as an explicit contract shim; keep them aligned to `07-01` planned endpoint behaviors rather than coupling this plan via `depends_on`):
    - `sync_judgment` caches and doesn\'t refetch when not stale.
    - `save_judgment` updates cached record and clears stale flags.
    - `callout_status` returns validated/outcome correctly for:
      - no judgments
      - only draft judgments
      - one final support
      - multiple finals with disagreement -> outcome uncertain
      - exact vs fallback key matching:
        - when stored judgments omit `target_id` but caller supplies `target_id`, `callout_status` returns the expected status via fallback to `(doc_id, citation_index, None)`.
    - NOTE (contract): ensure fixtures match `07-01` semantics:
      - export endpoint returns a RAW payload (string/bytes) suitable for download (no JSON-decoding).
      - judgment payload draft/final semantics are preserved (draft may have `verdict=None`; final requires a verdict).
  </action>
