  - Instantiate and reuse `JudgmentStore` (from `frontend/judgment_store.py`).
  - On render for the selected claim:
    - Call `judgment_store.sync_judgment(selected_claim)` to hydrate.
    - Render a compact control row:
      - Status select: `Draft` / `Final`.
        - UI label/value contract (BLOCKER): show human labels `Draft`/`Final` but send `status` to the backend as lowercase literals: `"draft"|"final"`.
      - Verdict radios or segmented buttons for `Support`, `Contradict`, `Uncertain`.
        - UI label/value contract (BLOCKER): show human labels `Support`/`Contradict`/`Uncertain` but send `verdict` to the backend as lowercase literals: `"support"|"contradict"|"uncertain"`.
        - Implement either:
          - Lowercase option values with human-facing labels (preferred), OR
          - Explicit mapping to lowercase immediately before calling `judgment_store.save_judgment(...)`.
      - Enforce locked semantics in UI:
        - Allow saving Draft with no verdict (represent as `verdict=None`).
        - Disallow saving Final without verdict (disable save + show inline hint).
    - Render a "Notes" section inline with structured fields (e.g., `rationale`, `caveats`, `followups`):
      - Fields are optional.
      - Use a collapsed-by-default expander after save:
        - Keep a per-claim key like `judgment-notes-open::{claim_id}`.
        - After a successful save, force it closed.
        - When there are existing notes, show a short preview line when collapsed.
  - Save action:
    - Add a `Save judgment` button that calls `judgment_store.save_judgment(...)`.
      - Ensure the payload passed to `save_judgment` uses lowercase literals for `status` and `verdict` (per backend `Literal[...]` models).
    - Include provenance on every save from `claim_queue.get_claim_record(selected_claim)`:
      - Always include: `doc_id`, `callout`, `reference_id`, `doi`, `author`, `year`, and `claim_text` snapshot.
      - Additionally, explicitly persist the callout tuple provenance fields when available: `citation_index`, `target_id`, and `sentence_id`.
        - Source these from the same current citation/callout selection state tuple used to render callout chips/buttons and compute callout status (preferred), OR
        - If a per-claim record already includes these fields, pull them from that record; otherwise, when the user selects a citation/callout, store the currently selected tuple in `st.session_state` so the claim card can reuse it when saving a judgment.
      - These provenance fields are REQUIRED to make VAL-03/VAL-04 (callout indicators + export mapping) deterministic and not reliant on ephemeral UI state.
    - Do NOT change the locked rule: verdict is still per-claim.
  - After save, rerun (`_rerun()`) to collapse notes and update callout styling.

- Add `frontend/assets/judgment.css` and inject it alongside existing style injections:
  - Keep it minimal: spacing, subtle borders, and outcome colors reused for callout chips.
  - No global redesign.
