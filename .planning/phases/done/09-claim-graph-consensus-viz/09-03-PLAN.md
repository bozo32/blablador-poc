<task type="auto">
  <name>Add claim-graph schemas + FastAPI endpoints</name>
  <files>backend/schemas.py, backend/main.py</files>
  <action>
1) Add response/request schemas for claim graph payloads:
   - Node: id, kind, label, properties (doc_id, sentence_id, claim_text, etc.)
   - Edge: edge_id, source_id, target_id, kind, properties (source/provenance), aggregates
   - Vote: reviewer_uid, verdict, confidence?, comment?, updated_at

2) Add endpoints (names can vary, keep REST-y):
   - `GET /graph/claim-subgraph?center_claim_id=...&hops=1..3&edge_cap=...&min_votes=...&sources=auto,manual,external_search`
   - `GET /graph/claim/{claim_id}` returns node details
   - `GET /graph/edge/{edge_id}/votes` returns all votes on edge
   - `PUT /graph/edge/{edge_id}/vote?reviewer_uid=...` upserts vote
   - `POST /graph/claim-link` creates a manual edge (uses active reviewer_uid as creator)
   - `DELETE /graph/claim-link/{edge_id}?reviewer_uid=...` deletes if creator
   - `GET /graph/claim/{claim_id}/candidates?limit=...` returns candidate neighbor edges without persisting

3) Candidate generation (MVP):
   - Use a deterministic lexical similarity score over claim_text (token overlap + SequenceMatcher is acceptable).
   - Exclude already-materialized neighbors.
   - Return top-N with a score.

4) Subgraph materialization rules:
   - Subgraph endpoint returns only materialized CLAIM_LINK edges.
   - Adding a candidate edge materializes it with `source="manual"` and sets `creator_uid`.
   - "Explore/expand" action may materialize top candidates as `source="auto"` and adds reviewer_uid to `explored_by`.
  </action>
  <verify>pytest -q</verify>
  <done>API can return a claim neighborhood graph, list edge votes, and accept reviewer-scoped votes.</done>
</task>
