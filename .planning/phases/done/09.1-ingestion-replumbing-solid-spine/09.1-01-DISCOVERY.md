# Phase 9.1.01 Discovery: Replumbing + Solid Spine

## Goal

Turn the replumbing decisions into an executable plan that can be run end-to-end and moved across machines, while keeping the existing POC workflow working.

## Decisions Already Made (Lock These)

- Deployment target: single VPS (initial)
- Platform support: macOS (Apple Silicon), Linux x86_64, Windows (Docker Desktop/WSL2)
- CPU-only
- Service interface: internal HTTP services
- Storage: S3-compatible object store (MinIO local, S3 later)
- Metadata store: Postgres
- Heavy services may run remotely: GROBID + fallback/OCR worker + model services
- Model access: route through a model gateway
- Inter-service auth: private network + service tokens

## Clarifying Questions (Only If We Hit Them)

1) Dependency locking choice
- `uv` lock vs `pip-tools` lock?

2) Transitional persistence
- Do we dual-write (filesystem + S3/Postgres) during rollout, or migrate immediately?

3) Remote networking
- WireGuard vs SSH tunneling vs campus private network?

Recommended default if blocked: dual-write during rollout; SSH tunnel in dev, WireGuard for VPS.

## Success Criteria (Concrete)

- Fresh machine: `docker compose up --build` starts UI + API + Postgres + MinIO + GROBID.
- Smoke flow: upload -> extraction job records exist -> artifacts are written to object store.
- Re-running the same job does not duplicate work (idempotency: `doc_id/work_id + settings_hash`).
