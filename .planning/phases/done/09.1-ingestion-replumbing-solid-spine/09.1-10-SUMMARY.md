# Phase 9.1 Plan 10: Settings + Workflow Versioning Summary

**Added Postgres-backed, versioned storage for project-scoped settings and workflow graphs, plus small additive API endpoints to inspect and append versions.**

## What Changed

- Added tables + indexes (idempotent) in `backend/db/migrate.py`:
  - `settings_bundles`, `settings_versions`, `settings_field_policies`
  - `workflow_definitions`, `workflow_versions`
- Added persistence helpers:
  - `backend/spine/settings_store.py` (bundle create/get, append version, latest)
  - `backend/spine/workflow_store.py` (definition create/list, append version, latest)
- Added additive API endpoints in `backend/main.py` (project scoped via `X-Project-Id`, defaulted for POC):
  - `GET /spine/settings` (latest)
  - `POST /spine/settings` (append version)
  - `GET /spine/workflows` (list)
  - `POST /spine/workflows` (create def + first version)
  - `POST /spine/workflows/{workflow_id}/versions` (append)

## Verification

- `GET /spine/settings` returns a bundle id
- `POST /spine/settings` appends a settings version
- `POST /spine/workflows` creates a workflow + version 1
- `POST /spine/workflows/{workflow_id}/versions` appends version 2 and `latest` matches
