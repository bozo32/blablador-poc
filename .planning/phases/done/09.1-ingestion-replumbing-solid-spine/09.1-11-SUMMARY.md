# Phase 9.1 Plan 11: Stable Locator Primitives Summary

**Added a durable locator primitive (project-scoped) so future evidence/entailment/annotation features can reference stable addresses inside document versions without relying on brittle page-number-only links.**

## What Changed

- Added Postgres table `locators` (idempotent) in `backend/db/migrate.py`:
  - `locator_id`, `project_id`, `created_by_user_id`, `document_version_id`, `type`, `payload_json`, `created_at`
- Added persistence helpers in `backend/spine/locators.py`:
  - `create_locator`, `get_locator`, `list_locators_for_document_version`
- Added additive API endpoints in `backend/main.py` (project scoped via `X-Project-Id`, defaulted):
  - `POST /spine/locators`
  - `GET /spine/locators/{locator_id}`
  - `GET /spine/document-versions/{document_version_id}/locators`

## Locator Payload Contract (initial)

- `type` is a free-form string (examples: `pdf_page_bbox`, `text_quote_anchor`).
- `payload_json` is opaque JSON and can contain multiple selectors (page, bbox, quote, offsets, etc.).

## Verification

- Created a locator for a newly ingested document_version_id.
- Verified get + list endpoints return the created locator.
