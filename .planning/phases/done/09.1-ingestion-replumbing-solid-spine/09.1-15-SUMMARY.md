# Phase 9.1 Plan 15: Spine-Only Mode + Wipe UX Summary

**The app now defaults to spine-only runtime (Postgres + object store) and can operate without `data/ingestion/**` present. A guarded wipe flow is added for the local POC.**

## What Changed

- Introduced `SPINE_MODE` (`legacy` / `dual` / `spine`) with default `spine`:
  - `backend/main.py`
  - `backend/ingestion_store.py` (legacy store becomes inert/disabled in `spine` mode)
- Compose defaults to spine-only runtime:
  - `docker-compose.yml` sets `SPINE_MODE=spine` for `app-api`
- Removed remaining filesystem listing tails in runtime paths:
  - `backend/main.py` no longer depends on `list_ingested_documents()` for ingest listing/ledger/reindex flows
  - `POST /ingest/reextract-all` schedules spine-backed extract+resolve tasks in spine mode (does not enqueue legacy worker)
- Added wipe everything flow:
  - Backend: `POST /dev/wipe` (requires `{ "confirm": "WIPE" }`)
    - truncates Postgres spine tables
    - deletes all objects from the works bucket
    - clears local sqlite stores (graph/span/claims)
    - removes local data dirs (ingestion, attachments, evidence runs, indexes, judgments)
  - UI: added a guarded "Wipe everything" button under Project -> Maintenance

## Verification

- `SPINE_MODE=spine` service starts and serves OpenAPI.
- `scripts/dev/smoke_ingest.sh fixtures/sample.pdf` succeeds (upload + extract + GET /ingest/{id}).
- `POST /dev/wipe` returns 422 without correct confirm, and wipes state when confirmed; `GET /ingest` returns empty afterward.
